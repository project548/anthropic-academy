Defining tools with MCP— MCP で tool を定義する基本パターン

Anthropic Academy / コース03 Model Context Protocol

① tool 定義の基本構造

MCP の tool は FastMCP の @mcp.tool() デコレータを使うのが最もシンプル。Python の関数定義に1行追加するだけで MCP tool になる。

必要3要素: ① 関数名 (tool 名) ② 型ヒント (input schema 自動生成) ③ docstring (説明文 → LLM が見る)

② 最小サンプル

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("calculator")

@mcp.tool()
def add(a: int, b: int) -> int:
    """2つの整数を足し算する"""
    return a + b

@mcp.tool()
def multiply(a: int, b: int) -> int:
    """2つの整数を掛け算する"""
    return a * b

if __name__ == "__main__":
    mcp.run()

③ MCP が自動でやってくれること

  1. JSON Schema 生成: 型ヒント (a: int) から自動で {"type":"integer"} を作る
  2. tool 一覧公開: tools/list 要求に自動応答
  3. 入力検証: Claude が間違った型を渡したら自動エラー
  4. 結果シリアライズ: 戻り値を MCP プロトコル形式に変換

pydantic.Field で各パラメータに description を付けると LLM の理解度が劇的に上がる。

⑤ tool 設計のベストプラクティス

  • 関数名は動詞ベース: get_weather, send_email
  • docstring は LLM の指示書: いつ使うか・何を返すかを書く
  • 引数は最小限: 多すぎると LLM が混乱
  • エラーは例外で投げる: raise ValueError("...") → MCP が結果に変換
  • 副作用がある操作は明示: docstring に「DB に書き込みます」など警告

⑦ コース02 Tool use との違い

  • コース02: tools=[{"name":..., "input_schema":...}] を手書き
  • MCP: @mcp.tool() デコレータ + 型ヒント で自動生成

同じ「tool 定義」だが、MCP の方が記述量が圧倒的に少ない。

⑧ 中学生向けに例えると

料理レシピで「材料・手順・出来上がり」を書くと、ロボットがそれを読んで実行してくれる。MCP では Python 関数 = レシピ・docstring = 「いつ作るか」のメモ・型ヒント = 材料リスト。

⑨ 理解度チェック

Q1. @mcp.tool() が自動でやってくれることは?

A. JSON Schema 生成 / tool 一覧公開 / 入力検証 / 結果シリアライズ。手書き不要。

Q2. tool の docstring は誰が読む?

A. LLM (Claude)。docstring を見て「この tool をいつ使うか」を判断する。

Q3. パラメータに説明を付けるには?

A. pydantic.Field(description="...") を使う。LLM の理解度が上がる。
