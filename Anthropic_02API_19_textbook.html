Module 6 ・ Lecture 19

Structured data — JSON や コードを「中身だけ」取り出すしくみ

Anthropic Academy / コース02 Claude with the Anthropic API

① 構造化データの取り出しってなに？

Web アプリで「JSONをコピペで使いたい」場面はとても多い。たとえば AWS の設定ファイル・API のテストデータ・CSV エクスポート…。

ところが、Claude に「JSON で書いて」と頼むと、親切心から マークダウンの枠で囲み + 英語の説明文を添えて 返してくる。これだとユーザーが JSON 部分だけを手で選ぶ手間がかかって体験が悪い。

図① 普通に頼んだ場合(左：枠付き+説明文) vs プレフィル+ストップ(右：中身だけ)

② どんなしくみ？(3つの仕掛け)

使う道具は 2つだけ。アシスタントメッセージの「プレフィル」と「ストップシーケンス」。

図② プレフィル+ストップシーケンスの3ステップ

キーアイデア: プレフィルしたメッセージを見た Claude は 「自分が既に応答を書き始めた」 と思い込む。だから続きの中身だけを生成する。

③ コードで書いてみよう

実装は驚くほど短い。3行だけ。

messages = []

add_user_message(messages, "Generate a very short event bridge rule as json")
add_assistant_message(messages, "```json")

text = chat(messages, stop_sequences=["```"])

変数 text には、説明文も囲みもない 生の JSON 文字列 が入る。

動きを追う: ① ユーザーが「JSONで」と頼む → ② アシスタントが「```json」と書き始めた状態にする → ③ Claude が中身を続ける → ④ 閉じの「```」を書こうとした瞬間に停止。

④ 返ってきた文字列の後処理

取得した text には、前後に余分な改行や空白が入っていることがある。簡単に整えてからパースすればOK。

import json

# 前後の余分な空白・改行を取り除いてからJSONとして読み込む
clean_json = json.loads(text.strip())

strip() = 前後の余白削り。json.loads() = 文字列を Python の辞書/リストに変換。

⑤ JSON 以外への応用

このテクニックは JSON 専用ではない。「説明なしで中身だけ欲しい」場面ならどこでも使える。

図③ 応用範囲のいろいろ

コツは 「Claude が自然に付けたがる囲み」を見抜いて、それをプレフィル+ストップに据える こと。

  • コード → マークダウンのコードブロック ( ``` )
  • リスト → 別の記号・改行
  • CSV → ヘッダー行を埋めておく等

⑥ 紙の例えで覚える

紙の例えAPI テクニック
友達に「JSON 書いて」とそのまま頼む普通の応答(枠線+解説まで付く)
「ここから書いてね」と紙の途中を指で押さえるプレフィル (add_assistant_message)
「閉じカッコ書こうとしたら筆を止めて」と約束ストップシーケンス (stop_sequences)
「囲みも解説もいらない、本文だけほしい」このテクニックの動機

⑧ 理解度チェック

Q1. なぜ Claude に「JSONで」と頼むと困ることがある？

親切心からマークダウンの枠線・ヘッダー・英語の説明文を付けてしまうので、ユーザーがコピペで使うとき余計な手間がかかるから。

Q2. このテクニックで使う2つの仕掛けは？

プレフィル(アシスタントメッセージの先頭を埋める) と stop_sequences(ストップシーケンス) の2つ。プレフィルで Claude を「中身を書く構え」にして、ストップで閉じ記号の手前で止める。

Q3. このテクニックは JSON 以外に何に使える?

Python コードスニペット、箇条書きリスト、CSV データ、その他「説明なしで中身だけほしい」整形済みコンテンツなら何でも。

Q4. text.strip() は何のため?

返ってきた文字列の前後に余分な改行や空白が入っていることがあるので、それを削ってからパースするため。
