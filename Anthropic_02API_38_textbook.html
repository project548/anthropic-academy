Module 9 ・ Lecture 38

Project overview— リマインダーアプリを題材に tool use を学ぶ

Anthropic Academy / コース02 Claude with the Anthropic API

① 何を作るのか

これから リマインダーアプリ を題材に tool use を実装していく。Claude に「未来の日付にリマインダーをセットする」方法を教えるプロジェクト。

ゴール: ユーザー「来週木曜の診察、リマインダーお願い」 → Claude「OK、リマインダーセットしました」 と返せるアプリ。

一見シンプル。でも実装してみると「Claude にはそのままだとできない壁」が3つも見えてくる。それを tool で1つずつ埋めにいく のがこの章の核心。

② Claude が抱える3つの壁

図① Claude の3つの限界 — それぞれを tool で外付け拡張する

この3つは、プロンプトを工夫しても 本質的には解決できない。なぜなら、Claude の内部に「今この瞬間の時刻」も「リマインダーを刺すシステム」も存在しないから。

③ 用意する3つのツール

ツール名役割埋める壁
get_current_datetime今の正確な日時を返す壁① 時刻があやふや
add_duration_to_datetime日時に「7日後」等を足す壁② 日付の足し算が苦手
set_reminder指定日時にリマインダーをセット壁③ メモ帳がない
簡単な順に1つずつ実装する。最終的に、ユーザーが「来週リマインドして」と言うだけで、Claude が 3つのツールを連携呼び出し して処理できる状態を目指す。

④ ユーザー体験 → 内部処理の対応

# ユーザーが言うこと(自然言語)
「来週木曜日の診察、リマインダーお願い」

# Claude が内部でやること(tool 連携)
1. get_current_datetime()
   → "2026-05-20 10:00"
2. add_duration_to_datetime(base="2026-05-20", days=8)
   → "2026-05-28 10:00"  ← 来週木曜
3. set_reminder(datetime="2026-05-28 10:00", message="診察")
   → success

# Claude がユーザーに返す
「OK、5月28日 10時に診察のリマインダーをセットしました」

⑤ 設計思想 — 限界はツールで外付け拡張

原則: モデルに限界があるなら、プロンプトで頑張って迂回するのではなく、ツールで能力を外付け拡張 する。

これは Claude API 設計の中核思想の1つ。「Claude に何でも教え込もうとする」より「足りない部分を tool で補う」方が、安全・確実・拡張可能。

例えば「正確な計算をやらせたい」なら、Claude にがんばらせるより calculator(a, b, op) ツールを渡す方が確実。「最新の株価」なら get_stock_price(symbol)。

⑥ 中学生向けに例えると

Claude = すごく賢い同級生。でも教室から出られないし、腕時計を持ってない、電卓も使えない、メモ帳もない。

学校の例えtool use の対応
腕時計をプレゼントするget_current_datetime ツール
電卓を貸してあげるadd_duration_to_datetime ツール
メモ帳と先生への伝言ルートを渡すset_reminder ツール
「お願い、来週木曜にリマインドして」ユーザーの自然言語入力
賢い子が3つの道具を順番に使って実行Claude の tool 連携呼び出し

⑧ 理解度チェック

Q1. このプロジェクトのゴールは?

ユーザーが「来週木曜の診察、リマインダーお願い」と自然言語で頼んだら、Claude が「OK、セットしました」と返せるリマインダーアプリを作ること。

Q2. Claude がそのままだと持ってない3つの能力は?

① 正確な現在時刻(時刻があやふや)
② 日付の足し算(「7日後の火曜」等が不安定)
③ リマインダー機能(記録 + 通知の仕組みが内部にない)

Q3. 3つの壁をどう解決する?

それぞれ専用の tool を作る:
① get_current_datetime
② add_duration_to_datetime
③ set_reminder
Claude が自分で「どの tool を呼ぶか」を選んで、順番に呼び出して使う。

Q4. このプロジェクトから学ぶ設計の原則は?

「モデルに限界があるなら、プロンプトで迂回するより、ツールで能力を外付け拡張する」。Claude に何でも教え込むより、足りない部分を tool で補う方が安全・確実・拡張可能。
