PDF input— Claudeに長文PDFを直接読ませる (テキストと画像両方を理解)

Anthropic Academy / コース02 Claude with the Anthropic API

① まず結論 — PDF入力って何?

Claude にPDFファイルをそのまま渡せる機能。テキスト抽出 + ページ画像認識 の両方を Anthropic 側で自動処理。あなたは type="document" ブロックで PDF を投げるだけ。

強み:
  • テキスト + 図表 + スキャン画像 まで全部理解
  • OCR を別途使わなくて良い
  • レイアウトを保ったまま分析 (表・カラム・ヘッダー)

② 制約条件

項目上限
ファイルサイズ32MB / PDF
ページ数100ページ / PDF
形式PDF のみ (.docx は要変換)
対応モデルClaude 3.5 Sonnet 以降 + Claude 4.x
100ページ超のPDFは分割して投げる。または Files API (Lecture 61) で事前アップロード + 大きいPDFを参照する方式に切り替え。

③ 最小コード — base64でPDFを渡す

import base64
import anthropic

client = anthropic.Anthropic()

with open("./report.pdf", "rb") as f:
    pdf_data = base64.standard_b64encode(f.read()).decode("utf-8")

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=4096,
    messages=[{
        "role": "user",
        "content": [
            {
                "type": "document",
                "source": {
                    "type": "base64",
                    "media_type": "application/pdf",
                    "data": pdf_data,
                },
            },
            {"type": "text", "text": "このPDFの要約を5項目で教えて"}
        ],
    }],
)

print(response.content[0].text)
注目: 画像と同じ pattern。type="document" + media_type="application/pdf"。複数 content block でテキスト質問と組合せ。

④ URL方式

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=4096,
    messages=[{
        "role": "user",
        "content": [
            {"type": "document", "source": {"type": "url", "url": "https://arxiv.org/pdf/2403.10131.pdf"}},
            {"type": "text", "text": "この論文のkey contributionを3つ抽出"}
        ],
    }],
)
用途: arXiv論文・公開資料・公的レポート (政府刊行物等) の自動分析に最適。

⑤ 何が読めるか — PDF入力で強い領域

用途プロンプト例
論文要約「要約・key contribution・実験結果を抽出」
契約書レビュー「リスク条項を5つ + 各々の影響度を分析」
議事録抽出「決定事項・アクションアイテム・担当者を箇条書きに」
請求書OCR「金額・宛先・支払期日をJSON形式で抽出」
財務諸表分析「表からKPI抽出 + 前期比較」
マニュアル理解「目次から該当章を選んで、操作手順を要約」

⑥ コスト感

PDF も トークン換算 される:

  • 1ページあたり 約 1,500〜3,000 トークン (テキスト + 画像合算)
  • 100ページPDFなら 150,000〜300,000 トークン (Claude Opus 4.7 input料金で約 $0.5〜$1)
  • 同じPDFで複数回質問する場合は prompt caching (Lecture 60) で90%節約可能
圧縮テク: 100ページ全部を毎回送らず、prompt caching で1回送って何度も質問するパターンが定石。

⑨ 失敗パターン

「100ページ超」エラー

PDFを2分割・3分割して順次投げる。または Files API (Lecture 61) を使って事前アップロード → 部分参照。

「32MB超」エラー

PDFを圧縮 (画像解像度ダウン) または分割。スキャンPDFが大きくなりがち。

スキャンPDF (画像のみ) で文字が読めない

解像度が低すぎる可能性。元のPDFをより高解像度で再スキャン or OCRを先にかけてからテキスト化して送る。

学校の例えPDF input の対応

⑫ 理解度チェック

Q1. PDF入力の制約は?

サイズ 32MB / ページ数 100ページ / 形式 PDF のみ。超える場合は分割 or Files API で対応。

Q2. type="image" と type="document" の違いは?

image は1枚の画像。document は 複数ページのPDF。document は Anthropic 内部でテキスト抽出 + 画像認識を自動分離するため、表やレイアウトを保ったまま分析できる。

Q3. PDF が100ページ超のときの対処は?

① PDFを分割して順次投げる ② 重要な章だけ抜粋して送る ③ Files API (Lecture 61) で事前アップロード + 参照。

Q4. 同じPDFで複数回質問する場合のコスト削減は?

Prompt caching (Lecture 60) を使う。1回目で PDF をキャッシュ → 2回目以降は cache_read 料金 (通常の 10%) で再利用。
