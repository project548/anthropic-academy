① 一言まとめ
AWS関連コードを 3形式（Python / JSON / regex）でクリーンに返す プロンプトを評価するため、Claudeで自動的にテストデータセットを生成 → dataset.json に保存する流れ。
① Goal設定 → ② Eval Dataset構造定義 → ③ Helper関数 + generate_dataset() 実装 → ④ 実行テスト → ⑤ dataset.json 保存。これでプロンプト評価パイプラインの「入口」が完成する。
② キーポイント
  • 1
    Step 1: Setting Up the Goal（ゴールを設定する）
    評価の出発点 = 「何を達成すれば成功か」を定量化できる状態。今回のプロンプトの要件は「3形式（Python / JSON / regex）のクリーンな出力のみ。説明・ヘッダー・前置きNG」。
    prompt = """ Please write a script in the following languages: ... """
    Key requirement: Clean output in one of three formats - NO explanations / headers / extra text.
  • 2
    Step 2: Creating an Evaluation Dataset（評価データセットを作る）
    プロンプトに流し込む 入力（タスク）の集合。データ構造は JSONオブジェクトの配列、各オブジェクトに "task" プロパティ。手作業 or Claude 自動生成の2択（このレクチャーは自動生成）。
    [ { "task": "Write a Python function that..." }, { "task": "Generate a JSON config for..." }, { "task": "Build a regex that matches..." } ]
  • 3
    Step 3: Generating Test Data with Code（コードで生成する）
    まず Claude を扱う 3つのヘルパー関数 を準備 → その上に generate_dataset() を実装。プロンプト内で「3形式すべてカバー / JSON配列で返す / AWS文脈」を明示する。
    def add_user_message(messages, text): messages.append({"role": "user", "content": text}) def add_assistant_message(messages, text): messages.append({"role": "assistant", "content": text}) def chat(messages, system="", temperature=1.0, stop_sequences=[]): response = client.messages.create( model=MODEL_NAME, max_tokens=MAX_TOKENS, system=system, temperature=temperature, stop_sequences=stop_sequences, messages=messages, ) return response.content[0].text
  • 4
    Step 4: Testing the Dataset Generation（生成をテストする）
    関数を実行して、3形式（Python / JSON / regex）すべてをカバーする 3つの異なるテストケース が返るか確認。AWS関連コーディングタスクに偏りがないかチェック。
    dataset = generate_dataset() print(dataset) # → 3 different test cases: # - Python function (AWS Lambda 等) # - JSON config (CloudFormation / IAM 等) # - Regex (CloudWatch logs 等)
  • 5
    Step 5: Saving the Dataset（保存する）
    後段の評価フェーズで再利用できるよう dataset.json としてファイル保存。git にコミットすれば 再現性 も担保される。
    with open("dataset.json", "w") as f: json.dump(dataset, f, indent=2)
    これでプロンプト評価パイプラインの「入口」が完成。後段（grader / scoring / iterate）に進める状態。
  • 6
    自動生成の3つの注意点
    ① API課金が発生（Claude呼び出し）
    ② temperature=1.0 で 多様性を確保
    ③ 自動生成データは 人間の品質チェックを別途通すと安全
    「Auto生成 = 完成」ではない。生成 → 目視レビュー → 必要なら手作業で補強、が実運用フロー。

④ 用語集
Eval Dataset
プロンプト評価で使う入力（タスク）の集合。JSON配列構造、各オブジェクトに "task" プロパティ。
generate_dataset()
Claudeを呼び出してテストデータを自動生成する関数。プロンプト内で「3形式 / JSON出力 / AWS文脈」を指示。

生成の多様性を最大化する設定。同じタスクが繰り返されず、3形式すべてがカバーされやすくなる。
dataset.json
生成したテストデータを保存するファイル。後段の評価フェーズで再利用、git管理で再現性を担保。

⑤ 理解度チェック
Q1
eval dataset の構造はどうなっていて、各オブジェクトにはどんなプロパティが入りますか？
答えを見る
構造: JSONオブジェクトの配列。各オブジェクトには "task" プロパティが入り、その値は「Claudeに何を達成してほしいか」を記述した文字列。
[ { "task": "Write a Python function that..." }, { "task": "Generate a JSON config for..." } ]
Q2
generate_dataset() のプロンプトで「必ず指示すべき3点」は？
答えを見る
① 3形式（Python / JSON / regex）すべてカバー するよう明示
② 出力フォーマットを JSON配列 で返すよう指定
③ AWS-specific というドメイン文脈を入れる
この3点が抜けると、生成データが偏ったり、後段でパースできなかったりする。
Q3
なぜ temperature=1.0 でデータを生成し、なぜ dataset.json としてファイル保存するのですか？
答えを見る
temperature=1.0 = 多様性最大化。同じタスクが繰り返されると評価データセットとして偏りが出るため、温度を上げて3形式すべてがカバーされやすくする。
dataset.json保存 = 後段の評価フェーズ（grader / scoring）で再利用 + git管理で再現性を担保。プロンプトv1とv2を 同じデータセット で比較できることが評価ワークフローの前提。
