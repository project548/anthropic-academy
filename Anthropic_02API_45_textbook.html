Using multiple tools— 複数ツール統合で完全なエージェント基盤を作る

Anthropic Academy / コース02 Claude with the Anthropic API

① 1ツールから複数ツールへ

#44 では 1つのツール(get_current_datetime)だけでループを回した。実アプリでは 複数のツールが協調して動く 必要がある。本章は run_conversation を 3ツール対応 に拡張する。

ツール名役割
get_current_datetime現在の日時を取得
add_duration_to_datetime日付の足し算(7日後・3週間後等)
set_reminderリマインダー登録
これで 「来週木曜にリマインドして」 のような自然言語依頼が、Claude の自動連鎖呼び出しで処理できる。エージェントらしいエージェントの完成。

② #44 からの変更点は2箇所だけ

# 変更1: run_tool が3ツール全部にルーティング
def run_tool(tool_name, tool_input):
    if tool_name == "get_current_datetime":
        return get_current_datetime(**tool_input)
    elif tool_name == "add_duration_to_datetime":
        return add_duration_to_datetime(**tool_input)
    elif tool_name == "set_reminder":
        return set_reminder(**tool_input)

③ 連鎖呼び出し — エージェントの正体

図① 逐次連鎖呼び出しの流れ(Turn 1 → 2 → 3)

核心: Claude が tool A の出力(June 27, 2050)を tool B の入力に渡す。プログラマが「次はこれ呼んで」と指示しなくても、Claude が自動で多段推論する。これが「エージェント」の正体。

④ 並列 vs 逐次連鎖 — 2つのパターン

パターン使うとき例
並列(#44)独立した情報が複数欲しい「HH:MM と SS の両方欲しい」 → 同ターン内で tool_use 2個
逐次連鎖(#45)tool B が tool A の出力を必要とする「177日後にリマインド」 → 日付計算 → リマインダー
両方 同じ run_conversation ループ で動く。Claude が状況に応じて自動で使い分ける。

図② 並列(同時要請) vs 逐次連鎖(A → B)

⑤ 新ツール追加の4ステップ

SkillJar 記事より、ツールを増やす標準パターン:

  1. ツール関数本体 を作る(普通の Python 関数)
  2. スキーマ を定義する(JSON で説明書)
  3. run_conversation の tools リスト にスキーマを追加
  4. run_tool に elif ケース を追加
中央のループロジック(while True 本体)は 絶対に触らない。これがモジュラー設計の強さ。新機能追加が「足すだけ」で済む。

⑧ オリジナル演習問題 (4問・実演用)

問題1: 別の時間表現で試す

課題: 「3週間後」「半年後」「来年の同じ日」のように、別の時間表現でリマインダーをセットさせてください。Claude が unit パラメータ("weeks" / "months" / "years")を使い分けるか観察。
試す質問例:
・「3週間後に提出物のリマインダーを」
・「半年後に健康診断のリマインダーを」
・「来年の同じ日に契約更新のリマインダーを」
観察ポイント
  • unit="weeks" / "months" / "years" どれを選ぶか
  • duration の数値(3 / 6 / 1)の選び方
  • 各 unit で正しく日付が計算されるか(月またぎ・うるう年等)

問題2: 別の事象でリマインダー

課題: 「来月の旅行の準備」「3日後の重要会議」など、別の文脈でリマインダーを試す。Claude の content 引数の選び方を観察。
試す質問例:
・「来週金曜の朝、健康診断のリマインダーお願い」
・「2週間後の打ち合わせ準備を思い出させて」
・「3日後に薬の処方箋更新のリマインダーを」
観察ポイント
  • Claude が ユーザー文から content を抽出する精度
  • 「朝」「夕方」等の時刻指定があった場合の対応(timestamp の時刻部分)
  • 曖昧な表現「来週」「2週間後」をどう解釈するか

問題3: 並列 vs 逐次連鎖の比較

課題: 両方のスタイルを比較する質問を投げる。
  • 並列:「今日が何日と何曜日か両方知りたい」 → 同ターンで複数 tool_use
  • 逐次:「来週月曜に会議のリマインダーを」 → 連鎖呼び出し
ヒント: ループ回数を可視化(#44 演習問題1の改造)してから2種類の質問を投げると、明確に違いが見える。
期待される観察
  • 並列: Turn 1 の response.content に tool_use ブロックが 2個(同じターンで両方要請)
  • 逐次: Turn 1 で1個 → Turn 2 で1個(別ターンで順番に要請)
  • Claude は 自動で判断。プログラム側で並列/逐次を切り替える必要なし

問題4: batch_tool を試す(発展)

課題: cell-2 に batch_tool_schema が定義されているが、ipynb では使われていない。これも run_tool / tools リストに追加して、Claude が batch_tool を選ぶか観察。
ヒント: batch_tool は「複数 tool 呼び出しを1つにまとめる」用のメタツール。invocations パラメータに複数の tool 呼び出し情報を配列で渡す。実装する場合は run_tool に batch_tool ケース追加 + 各 invocation を再帰的に run_tool で実行する形になる。
発展ポイント
  • batch_tool は 並列性をより明示的に 制御するパターン
  • ネストした構造のため Claude が選びにくい(普通は並列 tool_use の方が選ばれる)
  • 大量の似たツール呼び出しを1メッセージに圧縮したい時に有効

⑫ 理解度チェック

Q1. #44 から #45 で変更する箇所は何箇所?

2箇所だけ:
① run_tool に elif を追加
② run_conversation の tools= リストにスキーマを追加
中央の while True ループは一切触らない。これがモジュラー設計の強さ。

Q2. 並列と逐次連鎖の違いは?

並列: 独立した情報が複数欲しい時。Claude が同ターン内で tool_use ブロックを2個以上返す。
逐次連鎖: tool B の入力が tool A の出力に依存する時。Claude が Turn 1 で A を呼び、結果を受けて Turn 2 で B を呼ぶ。
Claude が 自動で使い分ける。プログラマは切り替えコードを書かなくていい。

Q3. ipynb cell-6 の実演で、ループは何回回る?

3回:
Turn 1: Claude が add_duration_to_datetime を要請 → "Monday, June 27, 2050"
Turn 2: Claude が結果を読んで set_reminder を要請 → null(登録成功)
Turn 3: Claude が最終応答(stop_reason="end_turn")→ ループ脱出

Q4. 新ツールを4つ目に追加するときの4ステップは?

① ツール関数本体を作る
② スキーマを定義
③ run_conversation の tools= リストにスキーマ追加
④ run_tool に elif ケース追加
ループ本体は触らない。これが「足すだけで増える」モジュラー設計。
