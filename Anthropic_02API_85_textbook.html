Routing workflows— 入力に応じて分岐先を選ぶ workflow パターン

Anthropic Academy / コース02 Claude with the Anthropic API

① パターン定義

Routing = 入力をまず分類して、その種類に応じた専用処理パスに振り分ける workflow パターン。「振り分け」がポイント。

使い分け: 入力種別ごとに最適なプロンプト・モデル・tool を使い分けたいとき。1つのプロンプトで全種類対応より精度UP。

② コード例 — カスタマーサポート振り分け

def route_inquiry(user_message: str) -> str:
    # Step 1: 分類 (軽量モデル)
    classify = client.messages.create(
        model="claude-haiku-4-5",
        max_tokens=50,
        messages=[{"role": "user", "content":
            f"以下の問い合わせを以下から1つ選んで答えて: "
            f"refund | technical | billing | general\n"
            f"問い合わせ: {user_message}"
        }]
    )
    category = classify.content[0].text.strip()

    # Step 2: カテゴリ別に専用処理に振り分け
    if category == "refund":
        return handle_refund(user_message)       # 返金専用フロー
    elif category == "technical":
        return handle_technical(user_message)    # 技術サポート
    elif category == "billing":
        return handle_billing(user_message)      # 課金問題
    else:
        return handle_general(user_message)      # 一般質問

③ 使い所

  • カスタマーサポート: 問合せ種別で専用フロー
  • 多言語対応: 言語検出 → 各言語専用処理
  • モデル使い分け: 簡単な質問は Haiku / 難しいのは Opus
  • セキュリティ: 危険入力検出 → リダイレクトor拒否

④ Routing の利点

  • 各分岐先のプロンプトが シンプル になる (1種類だけ対応すればよい)
  • コスト最適化: 分類だけ軽量モデル、本処理だけ高精度モデル
  • 専門化: 各分岐がスペシャリスト化 → 精度UP
ハイブリッド: 「Routing + Chaining」「Routing + Parallelization」も多い。例: routing で分岐 → 各分岐内で chaining。

⑤ 中学生向けに例えると

病院の受付。患者が来たら、まず受付で「内科?外科?歯科?」を聞いて、専門医のいる診察室に振り分ける。各医者は自分の専門だけに集中できる。
