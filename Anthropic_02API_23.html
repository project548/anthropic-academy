① 一言まとめ
プロンプトを 客観的な数値スコア で改善するための 5ステップ評価ワークフロー。「① プロンプト草案 → ② eval dataset 作成 → ③ Claude に流す → ④ grader で採点 → ⑤ プロンプト変更してリピート」。スコアが上がれば本物の改善、下がればただの変更。エンジニアリングの推測作業を排除する。
② キーポイント
  • 1
    Step 1: Draft a Prompt（プロンプト草案を作る）
    改善したい元のプロンプトをまず作成。シンプルなテンプレートから始めてOK。これがテストと改善の 基準点（baseline） となる。
    prompt = f""" Please answer the user's question: {question} """
  • 2
    Step 2: Create an Eval Dataset（評価データセットを作る）
    本番環境でプロンプトが処理する質問・リクエストの種類を表す サンプル入力集。3例〜数千例まで規模自由。手作業 or Claude で生成可。
    例（3問）: "2+2は？" / "オートミールはどうやって作るの？" / "月はどのくらい遠い？"
  • 3
    Step 3: Feed Through Claude（Claude に流す）
    データセットの各質問を プロンプトテンプレートに interpolate（差し込み） → 完成したプロンプトを Claude に投げて回答を取得。
    Please answer the user's question: What's 2+2?
  • 4
    Step 4: Feed Through a Grader（grader で採点）
    各回答を質と正しさで 1〜10 のスコア で採点。10 = 完璧、低スコア = 改善余地あり。grader は code grader / model grader / human grader のいずれか。
    例: 数学 → 10（正解）/ オートミール → 4（改善余地）/ 月 → 9（良い）
    平均: (10 + 4 + 9) ÷ 3 = 7.66
  • 5
    Step 5: Change Prompt and Repeat（変更して繰り返す）
    基準スコア（v1=7.66）を持っているので、プロンプトを変更 → 同じ評価プロセス → 新しいスコア（v2=8.7）を比較。客観的に改善が確認できる。
    prompt = f""" Please answer the user's question: {question} Answer the question with ample detail """
    v1 (7.66) → v2 (8.7) = 追加指示が効いたと確証
  • 6
    Prompt Scoring の3つの利点
    ① 異なるプロンプトバージョンを 数値で比較できる
    ② 最高スコア版を採用、または iterate を続けられる
    ③ 「変更が改善か単なる変更か」が 客観的に判別できる
    推測作業ベースの prompt engineering からの卒業 → data-driven 改善へ
③ 5ステップ詳細
Step 名称 やること アウトプット
1 Draft a Prompt 改善したい元プロンプトを書く baseline prompt
2 Create an Eval Dataset 本番想定の入力集を集める or Claude で生成 JSONリスト形式のテストデータ
3 Feed Through Claude 各データをテンプレに差し込み → API 呼び出し 各テストの Claude 回答
4 Feed Through a Grader 1〜10 スコア採点 → 平均値算出 baseline スコア（例: 7.66）
5 Change Prompt and Repeat プロンプト改良 → Step 3〜4 をループ 改善版スコア（例: 8.7）
Many different ways to assemble a workflow. Many different open source and paid options exist. 小規模から始めて必要に応じて規模拡大できる。
④ 用語集
eval workflow
プロンプト評価の一連の流れ。書く → データセット → Claude 実行 → 採点 → 改良 のサイクル。
eval dataset
プロンプトに差し込む質問やリクエストの集まり。3〜数千例まで規模自由。手作業 or Claude 生成。
prompt draft / baseline
改善前のシンプルなプロンプト。スコア比較の出発点。
grader
Claude の回答を1〜10で採点するシステム。Code grader / Model grader / Human grader の3種類。
iterate
プロンプトを修正して評価プロセスをループする行為。スコアの推移で改善の有無を判定。
prompt scoring
各プロンプト版に客観的な数値（平均スコア）を付ける仕組み。A/B 比較の根拠になる。

Q3
なぜ eval workflow を組むと「推測作業からの卒業」になるのですか？
答えを見る
主観で「これ良くなった気がする」ではなく、客観的なスコア（数値）で判断できるから。プロンプトを変更したとき、それが「改善」なのか「単なるバリエーション」なのかが数値で証明される。エンジニアリングにおける勘 → 計測へ転換。
