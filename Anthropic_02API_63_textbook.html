Code execution and the Files API— Claude にコード実行とファイル参照の二輪を持たせる

Anthropic Academy / コース02 Claude with the Anthropic API

① まず結論 — 何の組合せ?

本章は 2つのAnthropic組み込みtool を一緒に使う設計を学ぶ:

  • Code execution tool: Claude が Pythonコードを書いて実行 できる (sandbox)
  • Files API: ファイルを事前アップロードして file_id で参照
2つ揃うと: 大きなCSV/PDFを Files API でアップロード → Claude が「pandas でデータ集計」コードを書いて実行 → 結果テーブルとグラフを返す、というデータアナリストのような振る舞いが可能。

② Code execution tool とは

Anthropic 公式の サーバーサイドツール (#48 web_search と同じ仕組み)。Claude がコードを書く → Anthropic のサンドボックスで実行 → 結果を Claude が読んで応答に活用。

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=4096,
    tools=[{
        "type": "code_execution_20250825",
        "name": "code_execution"
    }],
    messages=[{
        "role": "user",
        "content": "1000以下の素数の平均値を計算して、ヒストグラムを描いて"
    }],
    betas=["code-execution-2025-08-25"]
)

# 応答に含まれるブロック:
# - text: Claude の判断
# - server_tool_use (name=code_execution, input={"code": "import sympy..."})
# - code_execution_tool_result (stdout / stderr / file outputs)
# - text: 最終応答 + 引用
特徴:
  • Python 環境 (pandas / numpy / matplotlib / scipy 等プリインストール)
  • サンドボックス分離 (ローカルファイルシステム触れない)
  • 実行結果の 標準出力・生成ファイル (CSV/PNG等) を Claude が読み取って活用
  • citation 自動付与 (どのコード片からこの結論を導いたか)

③ Files API と組み合わせる

# STEP 1: CSV を Files API にアップロード
file_obj = client.beta.files.upload(
    file=("sales.csv", open("./sales.csv", "rb"), "text/csv"),
)
file_id = file_obj.id

# STEP 2: file_id を message に渡しつつ code_execution tool を有効化
response = client.beta.messages.create(
    model="claude-opus-4-7",
    max_tokens=8192,
    tools=[{"type": "code_execution_20250825", "name": "code_execution"}],
    messages=[{
        "role": "user",
        "content": [
            {
                "type": "container_upload",
                "file_id": file_id  # ← Claude のサンドボックス内に配置
            },
            {
                "type": "text",
                "text": "sales.csv を読み込んで、月別売上の推移をグラフで見せて"
            }
        ]
    }],
    betas=[
        "code-execution-2025-08-25",
        "files-api-2025-04-14"
    ]
)
核心: type="container_upload" で file_id を渡すと、Claude のサンドボックス内に /mnt/user-data/sales.csv のような形で配置される → Claude が pandas で読み込んでコード実行。

④ 実行フロー (5段階)

1. ユーザー: 「sales.csv を分析して」
2. Claude: 内部判断「pandas で読み込みが必要」
3. server_tool_use: code_execution(code="import pandas as pd; df = pd.read_csv(...)")
4. Anthropic 実行 → stdout, 生成された .png ファイル等を Claude に返す
5. Claude: 最終応答「平均売上は X 円、トレンドは右肩上がり」+ グラフファイル参照
サーバーサイドtoolなので: あなたのコードでは tool_result を返さなくていい。1回の API 呼び出しで Files upload → Code 実行 → 結論まで完結。

⑥ サンドボックスの制約

項目制約
言語Python のみ (現時点)
パッケージ標準 + pandas / numpy / matplotlib / scipy / sympy / pillow 等プリインストール
追加 pip install不可 (固定セット)
ネットワーク外部APIアクセス不可 (サンドボックス分離)
ファイル書込サンドボックス内ファイルシステムのみ (永続なし)
実行時間1ターンあたり数十秒上限
メモリ制限あり (大容量データはチャンク処理)

⑦ 出力ファイルの取り出し

for block in response.content:
    if block.type == "code_execution_tool_result":
        # block.content に stdout, stderr, files が入る
        for f in block.content.get("files", []):
            file_id = f["file_id"]      # 出力ファイルの Files API ID
            filename = f["filename"]    # 例: "monthly_sales.png"

            # 出力ファイルを Files API でダウンロード
            content = client.beta.files.content(file_id)
            with open(filename, "wb") as fout:
                fout.write(content.read())
循環構造: Files API でアップロード → Claude がコード実行 → 結果ファイルが Files API に再保存 → ダウンロード。すべて Anthropic 内で完結。

⑧ Web search との組合せ (動的フィルタリング)

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=4096,
    tools=[
        {"type": "web_search_20260209", "name": "web_search"},
        {"type": "code_execution_20250825", "name": "code_execution"}  # 必須
    ],
    messages=[{"role": "user", "content": "最新の株価をAAPLとGOOGLで比較して"}]
)
# Claude がコードを書いて、Web検索結果から関連部分だけフィルタしてから読む
# → トークン消費削減 + 精度向上

⑨ コスト

  • Code execution: $0.05 / 実行時間1分 (短いコードなら無料に近い)
  • Files API: ストレージ料金は無料 (90日保持)
  • 生成された画像/CSV: 通常 input tokens としてカウント
  • prompt caching と組合せ: 入力ファイル部分をキャッシュ → 90%OFF も可能
注意: Code execution はコストの予測が難しい。長時間ループするコードを Claude が書くと課金が膨らむ。
→ 重要タスクは max_tokens / system prompt で「コードは30行以内」「実行時間は10秒以内」等のガード入れる。

問題1: 自分のExcel/CSVファイル (例: 家計簿・売上履歴) を Files API でアップロード → 「月別の支出推移をグラフ化して、最も使った費目TOP3を出して」と質問。生成された PNG を取り出す。

⑬ 理解度チェック

Q1. Code execution tool は何ができる?

Claude が Python コードを書いて、Anthropic のサンドボックスで実行。pandas / numpy / matplotlib 等使えて、データ分析・グラフ描画・検算・前処理を1回の API 呼び出しで完結。

Q2. Files API と Code execution はどう連携する?

① Files API で file_id 取得 ② messages に type="container_upload" で file_id 指定 ③ Claude のサンドボックスに自動配置 ④ Claude がコードで読み込み・分析。

Q3. なぜ web_search_20260209 (動的フィルタリング) は code_execution が必須?

動的フィルタリングは「Claude がコードを書いて検索結果を後処理」する仕組みなので、内部で code_execution tool が使われる。両方を tools 配列に含める必要あり。

Q4. サンドボックスでできないことは?

① 外部API呼び出し (ネットワーク遮断) ② 追加 pip install (固定パッケージのみ) ③ 永続ファイル保存 (実行終了で消える)。
→ これらが必要なら別途自前tool 経由で外に出す。
