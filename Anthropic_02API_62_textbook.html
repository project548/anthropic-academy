Prompt caching in action— 実コード例で動かして、usage の数字を観察する

Anthropic Academy / コース02 Claude with the Anthropic API

① 本章の目的

#60 (機能) と #61 (ルール) を学んだあと、いよいよ 実コード で動かして「キャッシュが効いている」 ことを確認する回。usage オブジェクトの読み方が中心。

3つの観察ポイント:
  1. 1回目: cache_creation_input_tokens が大きい / cache_read=0
  2. 2回目以降: cache_read_input_tokens が大きい / cache_creation=0
  3. レイテンシ: 2回目以降は応答開始が明らかに早い

② 実演用の前提

import anthropic, time

client = anthropic.Anthropic()
model = "claude-opus-4-7"

# 長文 system prompt (4096トークン以上必要)
big_system = "あなたは社内ヘルプデスクです。以下のFAQに基づいて答えてください。\n\n"
big_system += "[ここに 5000トークン以上の FAQ 本文を挿入]\n" * 100  # ダミー

# キャッシュ対象として system prompt を構造化
system_blocks = [
    {
        "type": "text",
        "text": big_system,
        "cache_control": {"type": "ephemeral"}
    }
]

③ 1回目の実行 — cache_creation を観測

t0 = time.time()
response1 = client.messages.create(
    model=model,
    max_tokens=512,
    system=system_blocks,
    messages=[{"role": "user", "content": "副業申請の手順は?"}]
)
elapsed1 = time.time() - t0

print(f"1回目: {elapsed1:.2f}秒")
print(response1.usage)
# Usage(
#   input_tokens=12,                          # 質問のみ
#   cache_creation_input_tokens=50000,        # ← FAQ全文を新規キャッシュ
#   cache_read_input_tokens=0,                # ← まだ何も読んでない
#   output_tokens=120
# )
観察: 50,000トークンの FAQ を新規 cache_creation。料金は 1.25倍 だが、これは 1度きり。

④ 2回目以降 — cache_read で爆速・90%OFF

t0 = time.time()
response2 = client.messages.create(
    model=model,
    max_tokens=512,
    system=system_blocks,  # 完全に同じ
    messages=[{"role": "user", "content": "有給休暇の取得方法は?"}]  # 質問だけ違う
)
elapsed2 = time.time() - t0

print(f"2回目: {elapsed2:.2f}秒")
print(response2.usage)
# Usage(
#   input_tokens=14,
#   cache_creation_input_tokens=0,            # ← 新規キャッシュなし
#   cache_read_input_tokens=50000,            # ← キャッシュから読み込み (90%OFF)
#   output_tokens=140
# )
体感: elapsed1 (1回目) vs elapsed2 (2回目) で 30〜50%レイテンシ短縮。コストは 約90%削減。

⑤ 節約額の計算 (実数値)

# Opus 4.7 料金: $5 / 1M input tokens

# 1回目: cache_creation 50000 × 1.25 = 62500トークン相当
#       + 通常input 12トークン = $0.3125

# 2回目: cache_read 50000 × 0.1 = 5000トークン相当
#       + 通常input 14トークン = $0.0250
#       → 約12.5倍コスト削減

# 100回繰り返した場合:
#   キャッシュなし: 50000 × 100 = 5,000,000トークン × $5/M = $25.00
#   キャッシュあり: $0.3125 + $0.0250 × 99 = $2.79
#   → 約9倍コスト削減

⑥ growing conversation (自動キャッシュ)

会話履歴が伸びる用途では「最後のメッセージに毎回 breakpoint を動かす」自動キャッシュが便利:

conversation = []

def chat(user_msg):
    conversation.append({"role": "user", "content": user_msg})
    response = client.messages.create(
        model=model,
        max_tokens=512,
        cache_control={"type": "ephemeral"},  # ← top-level (自動)
        system="...",
        messages=conversation,
    )
    conversation.append({"role": "assistant", "content": response.content[0].text})
    print(f"cache_read={response.usage.cache_read_input_tokens}, "
          f"cache_creation={response.usage.cache_creation_input_tokens}")
    return response

chat("Anthropic って何の会社?")
# 1回目: cache_creation=4500, cache_read=0

chat("Claudeのバージョン教えて")
# 2回目: cache_creation=400, cache_read=4500 (前回のsystem+履歴がHIT)

chat("Sonnet と Opus の違いは?")
# 3回目: cache_creation=500, cache_read=4900
自動キャッシュの利点: breakpoint が 常に最新メッセージ に移動 → 過去履歴が常にキャッシュから読まれる。コード書く側は意識せずに使える。

⑦ 階層的キャッシュ実演 — 4 breakpoint

response = client.messages.create(
    model=model,
    max_tokens=512,
    system=[
        {"type": "text", "text": "[全社共通指示]",
         "cache_control": {"type": "ephemeral"}},        # breakpoint 1
        {"type": "text", "text": "[このアプリ固有指示]",
         "cache_control": {"type": "ephemeral"}}         # breakpoint 2
    ],
    tools=[
        {..., "cache_control": {"type": "ephemeral"}}    # breakpoint 3
    ],
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "[巨大なFAQ全文]",
             "cache_control": {"type": "ephemeral"}},    # breakpoint 4
            {"type": "text", "text": "[今回のユーザー質問]"}
        ]
    }]
)
# usage に各キャッシュ層のヒット状況が反映される
使い分け:
  • 全社共通指示: 全アプリで共有
  • アプリ固有指示: アプリごとに別キャッシュ
  • tool定義: 滅多に変わらない
  • FAQ全文: 月1回更新
→ 1個変えても他の3個は生き残る。

⑧ デバッグ: キャッシュが効かない時のチェックリスト

cache_creation_input_tokens = 0 のとき

原因: 最小トークン数未満。Opus 4.7 なら 4,096 トークン必要。
→ system prompt を長くする or cache_control を付け間違えていないか確認。

cache_read_input_tokens = 0 のとき (2回目以降)

原因: 1回目と2回目で prefix が違う。1byte違いを探す:

  1. timestamp が system に混ざっていないか
  2. tool定義が動的生成されていないか
  3. JSONキーの順番が違っていないか
  4. image/tool_choice/thinking パラメータが変わっていないか

cache_read が一部しか効いてない

原因: breakpoint が複数ある場合、上層が無効化されて下層もミス。階層順序 (tools→system→messages) を意識して再配置。

レイテンシが期待ほど下がらない

原因: キャッシュは効いているが output 生成が支配的。max_tokens を見直し / Sonnet/Haiku に切り替え検討。

⑨ 実演スニペット — 効果を計測する完全コード

import anthropic, time

client = anthropic.Anthropic()
SYSTEM_TEXT = open("./long_faq.txt").read()  # 50000トークン相当

def run_with_cache(question, with_cache=True):
    system = [{"type": "text", "text": SYSTEM_TEXT}]
    if with_cache:
        system[0]["cache_control"] = {"type": "ephemeral"}

    t0 = time.time()
    response = client.messages.create(
        model="claude-opus-4-7",
        max_tokens=512,
        system=system,
        messages=[{"role": "user", "content": question}]
    )
    elapsed = time.time() - t0
    u = response.usage
    return {
        "elapsed": elapsed,
        "input": u.input_tokens,
        "cache_create": u.cache_creation_input_tokens or 0,
        "cache_read": u.cache_read_input_tokens or 0,
        "output": u.output_tokens,
    }

# 比較実演
print("=== キャッシュなし (3回連続) ===")
for q in ["副業申請は?", "有給は?", "住所変更は?"]:
    r = run_with_cache(q, with_cache=False)
    print(f"  {r['elapsed']:.2f}秒 / input={r['input']}")

print("=== キャッシュあり (3回連続) ===")
for q in ["副業申請は?", "有給は?", "住所変更は?"]:
    r = run_with_cache(q, with_cache=True)
    print(f"  {r['elapsed']:.2f}秒 / cache_create={r['cache_create']} cache_read={r['cache_read']}")

⑩ 中学生向けに例えると

学校の例えcaching in action の対応
1回目:「教科書ぜんぶ書き写してから質問する」cache_creation 発生 (高い)
2回目以降:「机に教科書あるから質問だけ」cache_read 発生 (安い)
「教科書置きっぱ」だから先生もすぐ答えられるレイテンシ短縮
「家で教科書を温める = pre-warm」事前にcache作成しておく
「机の様子をノートに記録」usage オブジェクト
核心: 動かしてみると 「数字で確認できる」。usageを見て「ちゃんと効いてるか」を毎リクエスト判定する習慣をつける。

⑪ 理解度チェック

Q1. 1回目と2回目の usage はどう違うのが正解?

1回目: cache_creation_input_tokens が大きい、cache_read=0
2回目: cache_creation=0、cache_read_input_tokens が大きい
これが見えなければ「キャッシュ設定間違い」を疑う。

Q2. cache_creation の料金倍率は?

1.25倍 (5分TTL) / 2.0倍 (1時間TTL)。2-3回再利用すれば回収できる損益分岐点。

Q3. cache_read の料金倍率は?

0.1倍 (= 90%OFF)。これがキャッシュの旨味の本体。

Q4. 自動キャッシュとは?

top-level cache_control={"type":"ephemeral"} を1個だけ指定する方式。Anthropic 側が「最後の cacheable block」に自動 breakpoint を置く。growing conversation で便利。
