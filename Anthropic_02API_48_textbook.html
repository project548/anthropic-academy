The web search tool— Claudeに最新情報をリアルタイム検索させる「サーバーサイドツール」

Anthropic Academy / コース02 Claude with the Anthropic API

① まず結論 — 何の話?

Claude の学習データは カットオフ日 までしか入っていない。「今日の天気」「最新のニュース」「直近の株価」等は答えられない。
Web search tool を使うと、Claude が 自分で検索クエリを作って → Anthropic がGoogle相当の検索を実行して → 結果を Claude に渡す という仕組みで リアルタイム情報 を答えられるようになる。

ツール名: web_search / type: web_search_20250305 (基本版) または web_search_20260209 (動的フィルタリング対応版)
料金: 1,000検索あたり $10 + 通常トークン料金

② Text editor tool との決定的な違い — サーバーサイドツール

#47 の Text editor tool は 「アプリ側」で実行。Claude が要請して、あなたのコードが実際にファイル操作した。
Web search tool は違う。Anthropic のサーバー側で検索が実行される。あなたのコードは一切検索しない。

核心: server_tool_use ブロックが返ってきても、あなたは tool_result を返さなくていい。検索→結果取得→Claude 応答まで 1回の API 呼び出し で全部完結。アプリ側のコードは「ただ tools=[web_search] と書くだけ」。

③ 最小コード — 3行で使える

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    messages=[{"role": "user", "content": "What is the weather in NYC?"}],
    tools=[{"type": "web_search_20250305", "name": "web_search", "max_uses": 5}],
)

これだけで Claude は:

  1. 「NYCの天気を知るには検索が必要」と判断
  2. server_tool_use で {"query": "NYC weather today"} を生成
  3. Anthropic サーバーが検索実行 → 結果取得
  4. web_search_tool_result ブロックに結果が入る
  5. Claude が結果を読んで、citation付き で最終応答

④ オプションパラメータ — 制御の細部

パラメータ用途
max_uses 1リクエスト内の検索回数上限。コスト爆発防止 (例: 5)
allowed_domains このドメインのみ結果に含める (例: ["wikipedia.org", "nytimes.com"])
blocked_domains このドメインは結果から除外 (信頼できないソースを排除)
user_location 地域に最適化した結果。{type, city, region, country, timezone} 
tools=[{
    "type": "web_search_20250305",
    "name": "web_search",
    "max_uses": 5,
    "allowed_domains": ["wikipedia.org", "nytimes.com"],
    "user_location": {
        "type": "approximate",
        "city": "Tokyo",
        "region": "Tokyo",
        "country": "JP",
        "timezone": "Asia/Tokyo"
    }
}]
注意: allowed_domains と blocked_domains は同時指定できない (どちらか一方)。

⑤ レスポンス構造 — citation 必須

Web search の応答には 引用(citation) が含まれる。Anthropicは「ユーザーに出力を見せる時は citation を必ず表示せよ」と公式に求めている。

# 応答 content blocks (順番に届く)
[
  # 1. Claude の判断テキスト
  {"type": "text", "text": "I'll search for when Claude Shannon was born."},

  # 2. Claude が作った検索クエリ
  {"type": "server_tool_use", "name": "web_search",
   "input": {"query": "claude shannon birth date"}},

  # 3. 検索結果 (Anthropic 自動挿入)
  {"type": "web_search_tool_result",
   "content": [{
     "type": "web_search_result",
     "url": "https://en.wikipedia.org/wiki/Claude_Shannon",
     "title": "Claude Shannon - Wikipedia",
     "page_age": "April 30, 2025"
   }]},

  # 4. Claude の最終応答 + citation
  {"type": "text",
   "text": "Claude Shannon was born on April 30, 1916, in Petoskey, Michigan",
   "citations": [{
     "type": "web_search_result_location",
     "url": "https://en.wikipedia.org/wiki/Claude_Shannon",
     "title": "Claude Shannon - Wikipedia",
     "cited_text": "Claude Elwood Shannon (April 30, 1916 – ..."
   }]}
]
citation の3要素: url / title / cited_text (最大150文字)
→ UIには 必ず リンク + 出典タイトル + 引用テキストを表示する。Perplexity 風UI が法的にも正しい実装。

⑥ 動的フィルタリング (web_search_20260209)

新版では Claude が コードを書いて検索結果を後処理 できる。大量のHTML を context に読み込まずに、関連箇所だけ抽出。

基本版 (20250305)動的フィルタリング版 (20260209)
全HTML を context に読み込む Claude が code execution でフィルタしてから読む
トークン消費が大きい 関連部分のみ取り込み → 効率的
全モデル対応 Opus 4.6/4.7 / Sonnet 4.6 のみ + code execution tool 同時必須
使い分け: 軽い質問なら基本版 / 技術ドキュメント漁り・citation検証 → 動的フィルタリング版

⑦ エラーコード — 5パターン

error_code意味
too_many_requestsレート制限超過
invalid_input検索クエリが不正
max_uses_exceededmax_uses 上限到達
query_too_longクエリ長すぎ
unavailable内部エラー
エラー時は課金されない — 検索成功した分だけ $10/1,000検索が加算される。

⑧ 料金とトークン管理

  • 検索コスト: 1,000検索 = $10 (1検索 = 1¢)
  • トークンコスト: 検索結果も input_tokens としてカウント (Claude が読むので)
  • citation の cited_text / title / url は無料 (input_tokens に入らない)
コスト感: 1検索 = 1¢ + 検索結果が数千〜数万トークン。max_uses=5 で1リクエスト約5¢ + トークン代。多用するアプリは prompt caching で結果を再利用するとコスト圧縮できる。

⑨ オリジナル演習問題 (3問)

問題1: 「最新ニュース要約」を作る

課題: ipynb 006 cell-2 のプロンプトを「今日のAI業界のニュースを3件要約して、各ソースのURLも添えて」に書き換える。tools=[{"type": "web_search_20250305", "name": "web_search", "max_uses": 5}] で実行。
確認ポイント:
・response.content の中に server_tool_use と web_search_tool_result がどれだけ含まれるか
・citations 配列の中身を表示 (url / title / cited_text)
・response.usage.server_tool_use.web_search_requests でコスト計算
期待される観察
  • Claude が 1〜3回 検索する (3件要約のため複数クエリを作る)
  • 各テキストブロックに citation が付く
  • page_age が最近の日付になっている (リアルタイム性確認)

問題2: 地域限定検索

課題: user_location を {type:"approximate", city:"Tokyo", country:"JP"} と {type:"approximate", city:"New York", country:"US"} に切り替えて、同じ「今日のおすすめレストラン」プロンプトを投げる。結果がどう変わるか比較。
観察: 検索クエリ自体は同じでも、Anthropic 側の地域シグナルで結果が変わる。citation の url も地域別になる (.co.jp / .com 等)。
応用
  • ユーザーごとに location を設定すれば、パーソナライズされた検索結果を出せる
  • 多言語アプリでは timezone も合わせて変える (「今日」の解釈が変わる)

問題3: domain filter で「信頼できるソースだけ」

課題: 「コロナワクチンの最新情報」をプロンプトに、allowed_domains=["who.int", "cdc.gov", "nih.gov", "mhlw.go.jp"] で実行。出力の citation がすべて指定ドメイン内か確認。
業務応用: 法務・医療・金融など「ソースの権威性が重要」な領域で必須テクニック。逆に blocked_domains で「reddit.com / facebook.com / twitter.com」を除外すれば、SNS噂をフィルタできる。
注意点
  • allowed_domains と blocked_domains は 同時指定不可
  • allowed 指定が厳しすぎると検索ヒット0件になる可能性
  • ドメインは末尾ドット無し・スキーマ無し (例: "wikipedia.org" のみ)

⑫ 理解度チェック

Q1. Web search tool と Text editor tool の決定的な違いは?

Text editor は クライアントサイド: あなたのコードが実行 → tool_result を返す。
Web search は サーバーサイド: Anthropic 側で完結。あなたは tool_result を返さない。1回の API 呼び出しで検索→結果取得→Claude応答まで全部終わる。

Q2. citation が必須なのはなぜ?

① 法的: Anthropic 公式が「ユーザーに出力を見せるなら citation を必ず表示せよ」と公式に求めている (著作権・情報源明示の責任分散)。
② UX: ユーザーが「この情報の出所は信頼できるか」を判断できる。Perplexity が成功した理由のひとつ。
③ Claude の判断ミス時に検証できる。

Q3. 検索コストを抑える方法は?

① max_uses を低めに設定 (例: 3-5)
② allowed_domains で信頼ドメインに絞る (関連性向上・無駄検索減)
③ prompt caching で過去の検索結果を再利用
④ ユーザー質問を 事前にフィルタ して、本当に検索が必要か判定する system prompt にする

Q4. allowed_domains と blocked_domains は同時に使える?

いいえ、どちらか一方のみ。両方指定すると invalid_input エラー。設計時に「ホワイトリスト型 (allowed) / ブラックリスト型 (blocked)」のどちらかに決める。
法務・医療等の高信頼性領域は allowed 型 / 一般用途で「SNS除外したい」程度なら blocked 型。
