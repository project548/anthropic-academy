① 一言まとめ

ユーザーの「送信」からClaude応答表示まで5段階の流れがあり、APIキー保護のため必ずサーバーを経由する。Claudeの内部処理はトークン化→埋め込み→文脈化→生成の4ステップ。

② 5段階のリクエストフロー

1
クライアント → サーバーユーザーが「送信」をクリック。アプリが自社サーバーにリクエストを送る
2
サーバー → Anthropic APIサーバーが安全に保管したAPIキーを使ってAnthropicに転送
3
Claude が処理トークン化・埋め込み・文脈化・生成の4段階で応答を作成
4
Anthropic API → サーバー生成テキスト・使用トークン数・停止理由を含む構造化レスポンスを返す
5
サーバー → クライアントサーバーが応答をアプリに転送し、UIに表示される

③ サーバーが必要な理由

  • クライアント（ブラウザ・アプリ）から直接 Anthropic API を叩いてはいけない
  • APIキーをクライアントコードに埋め込むと誰でも抽出・悪用が可能になる
  • 自社サーバーを中継役にして、APIキーを安全に保管・使用する

④ APIリクエスト必須4パラメータ

パラメータ説明例

⑤ Claudeの内部処理4ステップ

① トークン化

テキストをトークン（単語・部分語・記号）に分割。おおよそ1単語＝1トークンのイメージ。

② 埋め込み（Embedding）

各トークンを数値ベクトルに変換。意味的な関係性を数値で表現する。

③ 文脈化

周囲の単語に基づき各埋め込みを精緻化。多義語の適切な意味を強調（例：quantum）。

④ 生成

次の単語の確率を計算し、確率＋制御されたランダム性で1トークンずつ選択・生成。

⑥ 生成が止まる3条件

条件内容stop_reason値
最大トークン数到達指定した max_tokens の上限に達したmax_tokens
自然な終了シーケンス終了トークン（EOS）が生成されたend_turn
停止シーケンスあらかじめ定義した停止フレーズに遭遇したstop_sequence

⑦ 用語集

トークン
Claudeがテキストを分割する最小単位。単語・部分語・記号など
埋め込み（Embedding）
トークンを意味的関係を持つ数値ベクトルに変換したもの
max_tokens
1回の生成で出力できる最大トークン数
stop_reason
生成が止まった理由（end_turn / max_tokens / stop_sequence）
SDK
Anthropicが提供する公式ライブラリ。API呼び出しを簡素化
文脈化
周囲のトークンに基づき埋め込みを調整し、適切な意味を選ぶ処理
