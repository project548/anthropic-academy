① モデル採点 vs コード採点

② 3つの構文検証関数

図② 3つの検証関数 — 同じパターン(パース試行→成功10/失敗0)

import json, ast, re

def validate_json(text):
    try:
        json.loads(text.strip())
        return 10
    except json.JSONDecodeError:
        return 0

def validate_python(text):
    try:
        ast.parse(text.strip())
        return 10
    except SyntaxError:
        return 0

def validate_regex(text):
    try:
        re.compile(text.strip())
        return 10
    except re.error:
        return 0
共通パターン: ① パース or コンパイルを try ② 成功なら満点(10) ③ 例外なら0点。シンプルで100%再現性あり。

③ データセット側の対応

どの検証器を使うか判別するため、テストケースに format フィールドを追加する。

{
    "task": "Create a Python function to validate an AWS IAM username",
    "format": "python"
}

generate_dataset() のプロンプトを更新して、自動的に format を含めるよう書く。

④ プロンプト改善

  • Respond only with Python, JSON, or a plain Regex
  • Do not add any comments or commentary or explanation

さらにアシスタントプレフィルで ```code を入れておく:

add_assistant_message(messages, "```code")

事前にフォーマット(python/json/regex)を指定しなくても、Claude が判断して中身だけ書こうとする。

⑤ スコアの合成

モデル採点とコード採点を平均して、最終スコアにする。

model_grade = grade_by_model(test_case, output)
model_score = model_grade["score"]
syntax_score = grade_syntax(output, test_case)

score = (model_score + syntax_score) / 2

図③ スコア合成例 (7 + 10) / 2 = 8.5

重み調整も可能: 内容重視なら model_score * 0.7 + syntax_score * 0.3、構文重視なら逆比。用途次第。

⑧ 理解度チェック

Q1. コードグレーダーが見るのは何?

構文の正しさ だけ。「これは valid な JSON/Python/regex か」をプログラムでチェック。意味の正しさはモデルグレーダーに任せる。

Q2. なぜ format フィールドが必要?

どの検証器(validate_json/python/regex)を使うか判別するため。テストケース側で「これは Python」「これは JSON」と先に伝えておく。

Q3. スコア合成で気をつけることは?

用途に応じて重みを調整すること。内容重視なら model*0.7 + syntax*0.3、構文厳密なら逆比。デフォルトは等重みの平均。

Q4. コードグレーダーの限界は?

期待フォーマットが既知の場合しか使えない(format フィールドが必要)。フォーマットが事前に決まらない自由な文章生成には不向き。
