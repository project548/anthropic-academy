Module 9 ・ Lecture 40

Tool schemas— Claude にツールを説明する JSON 取扱説明書

Anthropic Academy / コース02 Claude with the Anthropic API

① Tool schema とは何か

Tool schema = 関数の説明書を JSON で書いたもの。これを Claude に渡さないと、Claude はツールの存在に気づけない。

図① 関数本体 + スキーマ(取説) → Claude が使える

核心: 関数だけ渡しても Claude は「中身ブラックボックスの謎の道具」しか見えない。スキーマで「何を・いつ・どう」使うかを言葉で説明 して初めて、Claude は安全に呼べるようになる。

② 良い description の4要件

書くべきこと例
何をする道具か「現在の日時を指定書式で返す」
いつ Claude が使うべきか「ユーザーが現在時刻を尋ねたとき」
何を返すか「'2024-01-15 14:30:25' 形式の文字列」
各引数の意味date_format は strftime 書式コードの文字列

3〜4文程度が目安。短すぎると Claude が判断ミスする、長すぎるとトークンを食う。

③ スキーマを楽に作るコツ — Claude に書かせる

ゼロから JSON を書かなくていい。Claude にお願いする のが正攻法。

  1. ツール関数のコードをコピー
  2. Claude に「これの JSON スキーマを書いて」と頼む
  3. Anthropic 公式 tool use ドキュメントをコンテキストに添付
  4. ベストプラクティスに沿った形で生成してくれる
プロンプト例:
"Write a valid JSON schema spec for the purposes of tool calling
 for this function. Follow the best practices listed in the
 attached documentation."
(添付: Python 関数コード + tool use ドキュメント)
Why? 手書きだと typo・必須キー漏れ・型ミスが起きやすい。Claude に書かせれば 仕様に沿った形式 で出してくれる。生成後に微調整すればOK。

④ スキーマの実体 — 完全な例

def get_current_datetime(date_format="%Y-%m-%d %H:%M:%S"):
    if not date_format:
        raise ValueError("date_format cannot be empty")
    return datetime.now().strftime(date_format)

get_current_datetime_schema = {
    "name": "get_current_datetime",
    "description": "現在の日時を指定書式で返す。ユーザーが現在時刻を尋ねたときに使用。",
    "input_schema": {
        "type": "object",
        "properties": {
            "date_format": {
                "type": "string",
                "description": "strftime 書式コードの文字列",
                "default": "%Y-%m-%d %H:%M:%S"
            }
        },
        "required": []
    }
}
キー意味
name関数名(Python の関数名と一致させる)
description道具の説明(何を・いつ・何を返すか)
input_schema引数の構造(JSON Schema 形式)
properties各引数の定義(型・説明・デフォルト)
required必須引数のリスト(デフォルト値があるなら省略可)
命名規範: 関数名 + 関数名_schema。これで関数とスキーマがペアで一目で分かる。

⑤ 型安全に書く — ToolParam

from anthropic.types import ToolParam

get_current_datetime_schema = ToolParam({
    "name": "get_current_datetime",
    "description": "現在の日時を指定書式で返す",
    "input_schema": { ... }
})

ToolParam で囲むと、エディタが型エラーを 事前に 検出してくれる。必須キーの抜け漏れがコード書いた時点で分かる。

必須ではないが、保守性・チーム開発・将来の API 変更追従の観点で 推奨。

⑧ 理解度チェック

Q1. なぜ関数本体だけでなくスキーマも必要なの?

Claude は関数の中身(Python コード)を読まない。スキーマ(description / input_schema)で「何の道具か・どう使うか・何が必須か」を 言葉で説明 されて初めて、適切なタイミングで適切な引数で呼べる。スキーマなしで関数だけ渡しても、Claude は「謎の道具」として無視する。

Q2. description には何を書くべき?

4要件:
① 何をする道具か
② いつ Claude が使うべきか
③ 何を返すか
④ 各引数の意味
3〜4文程度がベスト。短すぎると判断ミス、長すぎるとトークン無駄。

Q3. スキーマを楽に書くコツは?

Claude 自身に書かせる。Python 関数コード + Anthropic 公式 tool use ドキュメントを添付して「JSON スキーマを書いて」と頼めば、ベストプラクティスに沿った形で生成してくれる。手書きより typo・キー漏れ・型ミスが減る。

Q4. ToolParam を使うメリットは?

エディタが型エラーを 事前に 検出してくれる(必須キーの抜け漏れ・スペルミス・型ミスマッチ)。必須ではないが、保守性とチーム開発の観点で推奨。from anthropic.types import ToolParam で読み込み、ToolParam({...}) で囲むだけ。
