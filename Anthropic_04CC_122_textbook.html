Module 5 ・ Lecture 122 ・ 落とし穴集

Gotchas around hooks— Hooks 運用でハマる「落とし穴」と回避策

Anthropic Academy / コース04 Claude Code

① この章の位置づけ

Hooks は強力だが、運用で 地雷を踏みやすい 領域でもある。実際にハマる典型パターンと回避策を集めた回。

核心: 「動いた!」と喜ぶ前に「これ無限ループにならない?」「セッション遅くならない?」「セキュリティ大丈夫?」を点検する。

② Gotcha 1: 無限ループ

症状: PostToolUse hook の中で Edit を呼ぶ → その Edit が PostToolUse を発火 → 無限ループでセッション破壊。
# ❌ NG: PostToolUse 内で再帰的に編集を呼ぶ
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit",
      "command": "node script-that-calls-edit.js"  // 危険!
    }]
  }
}

# ✅ OK: 別ロジック (フォーマッタ等) を直接呼ぶ
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit",
      "command": "prettier --write $FILE_PATH"
    }]
  }
}

③ Gotcha 2: blocking hook が遅い

症状: blocking hook が毎回 3秒 かかる → tool 実行のたびに待たされる → 体験が悪い。
  • blocking hook は 100ms 以下 を目標に
  • 重い処理は非同期 (PostToolUse + 非 blocking)
  • npm パッケージ取得を毎回するとかは絶対 NG
  • キャッシュやプリロード推奨

④ Gotcha 3: stdout/stderr の混乱

症状: hook の stdout に余計なものが入って Claude の context を汚す or tool 結果が壊れる。
  • stdout = Claude に渡る → 必要なものだけ書く
  • stderr = 人間ターミナルに表示 → ログ・警告はこちら
  • debug print は console.error で stderr に
  • 素通しなら stdin を stdout にそのまま echo

⑤ Gotcha 4: matcher の正規表現ミス

症状: matcher が広すぎて全 tool で発火 / 狭すぎて全く発火しない。
# ❌ 広すぎ
"matcher": ".*"          // 全 tool で発火 → 重い + 副作用大

# ❌ 狭すぎ
"matcher": "WriteOnly"    // 該当 tool なし → 永遠に発火しない

# ✅ ちょうど良い
"matcher": "Write|Edit"   // Write と Edit のみ
"matcher": "Bash"         // Bash のみ

⑥ Gotcha 5: 環境依存

症状: 自分の環境では動くが、別 OS / 別マシンで動かない。
  • シェル前提 (bash 専用) → Windows で動かない
  • 絶対パスハードコード → 別マシンで壊れる
  • 外部コマンドが必要 (prettier 等) → インストールされてないと無言で失敗
  • $CLAUDE_PROJECT_DIR 等の環境変数を活用

⑦ Gotcha 6: セキュリティ盲点

症状: 他人の settings.json を信用してインストール → 悪意ある hook が実行されて被害。
  • Hook は あなたの権限で実行される (任意コマンド実行)
  • OSS の settings.json をコピペする前に 必ず中身を読む
  • 機密情報を外部に送信する hook がないか確認
  • .claude/settings.local.json は .gitignore へ

⑧ Gotcha 7: デバッグできない hook

症状: hook が動いてるか分からない / エラー出てるか分からない。
  • ログ追記を仕込む: echo "[$(date)] hook fired" >> ~/.claude/logs/hook.log
  • matcher を一旦 ".*" にして発火を確認
  • command を echo にして変数値を確認
  • --debug オプションで Claude Code 起動

⑨ チェックリスト (hook 投入前)

  • [ ] 無限ループの可能性はないか?
  • [ ] blocking なら 100ms 以下か?
  • [ ] stdout/stderr は意図通り使い分けてるか?
  • [ ] matcher は意図したスコープか?
  • [ ] 他環境でも動くか? (OS / PATH)
  • [ ] 悪意ある操作してないか? (信頼できるソース?)
  • [ ] ログで確認できる構造になってるか?

⑩ 中学生向けに例えると

家のセンサー自動化を仕込む時の「あるある失敗」集。「人感センサー → 照明 ON」は良いが、「照明が ON になると人感センサーが反応する」配置だと無限ループ。Claude Code の hook も同じ。設置前に動作を頭でシミュレーションする。
