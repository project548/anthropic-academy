① まず結論 — MCP clientって何?

MCP (Model Context Protocol) は AI と外部システムをつなぐ USB-C 規格。前章 (#65 Introducing MCP) でコンセプトを学んだあと、本章は 「繋ぐ側」= クライアント の世界。

3つの登場人物:
  1. Host: アプリ全体 (Claude Desktop, Cursor, VS Code等)
  2. Client: Host内で1つのMCPサーバーと1対1で対話 する接続管理コンポーネント
  3. Server: 外部システム (DB / Google Calendar / Figma等) を MCP 規格で公開する側

USB-Cの真意: どのクライアントでも 同じMCPサーバーが使える。Slack向けMCPサーバーを書けば、Claude Desktop でも Cursor でも VS Code でも使い回せる。

③ Host・Client・Server の三層構造

図① Host 内に複数 Client → 各 Client が別 Server と1対1

核心: Host は複数の Server を扱うが、Client は1つのサーバー専属。これにより接続管理がシンプル + セキュリティ境界が明確。

④ Transport — どうやって通信する?

Transport用途通信方式
stdioローカル子プロセス標準入出力で JSON-RPC やり取り
HTTP + SSEリモートサーバー (旧版)HTTP POST + Server-Sent Events
Streamable HTTPリモートサーバー (新版・推奨)単一HTTPエンドポイントで双方向
選び方:
  • ローカル開発: stdio (子プロセスとして起動)
  • 本番リモート: Streamable HTTP (新版が推奨・SSEは段階廃止)
  • SaaS統合: Streamable HTTP + OAuth 認証

⑤ Claude Desktop での設定例

// claude_desktop_config.json (macOS: ~/Library/Application Support/Claude/)
{
  "mcpServers": {
    "weather": {
      "command": "python",
      "args": ["/Users/abi/work/weather-mcp/server.py"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "ghp_xxx..." }
    },
    "slack": {
      "url": "https://slack-mcp.example.com/mcp"
    }
  }
}
3パターン同居:
  • weather: stdio (Pythonローカルプロセス)
  • github: stdio (npx で外部パッケージ実行)
  • slack: HTTP (リモートMCPサーバーURL)
→ 1つのHostから複数のClient接続を同時に張れる。

⑥ Claude Code での設定 (CLI)

# 追加
claude mcp add weather python /Users/abi/work/weather-mcp/server.py

# 一覧
claude mcp list

# 削除
claude mcp remove weather

# HTTPサーバー追加
claude mcp add slack --transport http https://slack-mcp.example.com/mcp

# Scope (project / user / system)
claude mcp add --scope project github npx -y @modelcontextprotocol/server-github
scope の違い:
  • --scope project: 今のプロジェクトのみ (.claude/mcp.json)
  • --scope user: 自分のホームディレクトリ全部 (デフォルト)
  • --scope system: マシン全体 (要権限)

⑦ クライアントが Server に頼める6種のリクエスト

リクエスト意味例
tools/listサーバーがどんなツールを提供してるか問い合わせget_weather, send_message 等を列挙
tools/call特定ツールを実行依頼get_weather(city="Tokyo")
resources/listサーバーが提供する読み取り専用データファイル一覧・DBスキーマ等
resources/read特定リソースを読むspecific_file.md の中身
prompts/listサーバーが提供する定型プロンプト「障害レポート作成テンプレ」等
prompts/get特定プロンプト取得テンプレ + 動的補完
3本柱: Tools (実行) / Resources (データ参照) / Prompts (テンプレ取得)。これがMCPの中心概念。

⑧ Capability Negotiation — 接続時のハンドシェイク

# Client → Server: 「自分はこんな機能サポートしてるよ」と申告
initialize {
  protocolVersion: "2025-06-18",
  capabilities: {
    sampling: {},      # client が Server からの LLM 呼び出しを許可
    elicitation: {},   # client が user 入力収集を許可
    roots: {listChanged: true}  # フォルダ root 共有
  }
}

# Server → Client: 「私はこれをサポートします」と返す
{
  capabilities: {
    tools: {listChanged: true},
    resources: {listChanged: true, subscribe: true},
    prompts: {listChanged: true}
  }
}

# その後はお互いに sampling / tools/call / resources/read 等を投げる
核心: 接続最初に「お互い何できる?」を確認 → 以降は 合意した機能のみ 使う。プロトコルバージョン違いも吸収。

⑨ よくあるクライアント側ハマりポイント

1. 設定ファイルの場所が分からない

クライアントごとに違う:

  • Claude Desktop (macOS): ~/Library/Application Support/Claude/claude_desktop_config.json
  • Claude Desktop (Windows): %APPDATA%\Claude\claude_desktop_config.json
  • Cursor: ~/.cursor/mcp.json or .cursor/mcp.json (project)
  • Claude Code: claude mcp list で確認

2. サーバーが起動しない

stdio の場合: command + args が正しいか確認。Path が通っているか。実行権限 (chmod +x) があるか。ターミナルで手動実行してエラーメッセージを確認。

3. tool/call で「Permission denied」

Capability negotiation が成立してない or scope が間違っている可能性。設定の env / args をチェック。

4. リモートMCP接続で証明書エラー

HTTPS必須。自己署名証明書なら検証スキップオプションを設定(本番非推奨)。

⑩ Claude API での MCP 接続

response = client.beta.messages.create(

    max_tokens=4096,
    mcp_servers=[
        {
            "type": "url",

        }
    ],
    messages=[{"role": "user", "content": "#generalに『おはよう』と投稿して"}],
    betas=["mcp-client-2025-04-04"]
)
応用: 自前のチャットUIにMCPサーバーを統合 → Claude が自動的に「適切なツール」を選んで呼ぶ。

⑪ 中学生向けに例えると

学校の例えMCP の対応
学校 = USB-C ポートがあるHost (Claude Desktop等)
USB-C ケーブル = 共通の繋ぎ口MCP プロトコル
マウス・キーボード・モニター = 周辺機器MCP Server (Slack/Calendar/DB)
「マウス担当」「キーボード担当」と分業Client A / Client B (1対1)
挿した瞬間「これマウスです」「私キーボード」capability negotiation
核心: 「自社専用の繋ぎ方」を毎回作らない。USB-Cのような共通規格 で、誰が作ったツールでも組み合わせ自由に。

⑬ 理解度チェック

Q1. MCP の喩えは?

AI 用の USB-C 規格。どの AI アプリ (Claude / ChatGPT / Cursor / VS Code) でも、共通プロトコル MCP を介して、同じMCPサーバーが使い回せる。

Q2. Host と Client の違いは?

Host = アプリ全体 (Claude Desktop)
Client = Host内で1サーバーと1対1で対話する接続管理コンポーネント
Host は複数 Client を抱える。各 Client は1サーバー専属。

Q3. transport の3種は?

① stdio (ローカル子プロセス) ② HTTP+SSE (旧版リモート) ③ Streamable HTTP (新版リモート・推奨)
→ ローカルなら stdio / 本番なら Streamable HTTP。

Q4. MCPの3本柱は?

Tools (実行) / Resources (データ参照) / Prompts (テンプレ取得)。tool=動詞・resource=名詞・prompt=テンプレ、と覚える。
