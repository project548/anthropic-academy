② 問題セット (理解度チェック)

Q1. Claude API で messages.create に必須のパラメータは?

A. model / max_tokens / messages の3つ。temperature は任意。

Q2. マルチターン会話で過去履歴を保持する方法は?

A. messages 配列に user/assistant を交互に積む。Claude API はステートレスなのでクライアント側で履歴管理。

Q3. Tool use フローの4ステップは?

A. ① schema 定義 → ② Claude が tool_use 出力 → ③ クライアントが実行 → ④ tool_result を返して再呼び出し。

Q4. Prompt caching の効果は?

A. 同じ前置きの再利用で input トークン課金を 90% 削減・latency も大幅短縮。cache_control: {type: "ephemeral"} でマーク。

Q5. Fine-grained tool streaming の利点は?

A. tool input が完成する前から実行開始可能。eager_input_streaming パラメータで有効化。大きい input でも早期実行。

Q6. RAG の基本フローは?

A. ① ドキュメントを embedding 化して保存 → ② query を embedding 化 → ③ 類似度検索 → ④ 取得チャンクを context に注入 → ⑤ Claude に質問。

Q7. Extended thinking はいつ使う?

A. 複雑な推論・数学・計画立案が必要なとき。thinking: {type:"enabled", budget_tokens: 16000} で有効化。

Q8. Citations 機能の役割は?

A. Claude が参照した document のどの部分を引用したか自動的に返す。出典明示が必要な業務 (リサーチ・法務) で必須。

Q9. PDF input の最大ページ数は?

A. 100ページ・32MB まで直接 document ブロックで送信可能。それ以上は Files API でアップロード。

Q10. Workflow と Agent の違いは?

A. Workflow = 事前にフロー固定 (人間設計) / Agent = LLM が動的に次のアクション判断。本番は workflow 推奨、限定部分のみ agent 化。

Q11. Parallelization と Chaining の違いは?

A. Parallel = 独立タスクを並列実行 (asyncio.gather) / Chain = 依存タスクを逐次実行 (前段の出力 → 次段の入力)。

Q12. Agent の終了条件は?

A. response.stop_reason が "tool_use" 以外 ("end_turn" 等) のとき。それまで tool 実行と再呼び出しをループ。
