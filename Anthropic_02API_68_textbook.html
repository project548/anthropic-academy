Defining tools with MCP— @mcp.tool() デコレータでPython関数を tool 化する

Anthropic Academy / コース02 Claude with the Anthropic API

① まず結論 — どう書く?

FastMCP で tool を定義するのは 関数1つに @mcp.tool() を付けるだけ。type hints と docstring から自動的に JSON schema が生成され、Claude が読み取って活用できる。

魔法は3要素:
  1. @mcp.tool() デコレータ
  2. 型ヒント (引数・返り値の型)
  3. docstring (Claudeに伝える説明)

② 最小例 — 1分で書ける tool

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("weather")

@mcp.tool()
def get_weather(city: str) -> str:
    """Get the current weather for a specific city.

    Args:
        city: The city name, e.g. "Tokyo", "New York"

    Returns:
        A short string describing current weather.
    """
    return f"{city}: Sunny, 22°C"

if __name__ == "__main__":
    mcp.run(transport="stdio")
これだけで動く: Claude Desktop に登録すれば、ユーザーが「東京の天気は?」と聞いたとき Claude が get_weather(city="Tokyo") を呼んでくれる。

③ 自動生成される JSON schema

{
  "name": "get_weather",
  "description": "Get the current weather for a specific city.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "The city name, e.g. \"Tokyo\", \"New York\""
      }
    },
    "required": ["city"]
  }
}
自動化のポイント:
  • 関数名 → name
  • docstring 1行目 → description
  • 引数の型ヒント → inputSchema.properties
  • Args ブロック → 各プロパティの description
  • デフォルト値なし → required

④ 複雑な型 — Pydantic で構造化

from pydantic import BaseModel, Field
from typing import Literal

class ReminderInput(BaseModel):
    content: str = Field(description="リマインダーの内容")
    timestamp: str = Field(description="ISO 8601形式の日時")
    priority: Literal["high", "medium", "low"] = "medium"

@mcp.tool()
def set_reminder(input: ReminderInput) -> dict:
    """Set a reminder.

    Returns:
        Dict with status and created reminder id.
    """
    return {"status": "ok", "id": "rem_001"}
Pydantic の威力: 複雑な構造化引数も型安全に定義。Claude が「priority」が "high"/"medium"/"low" のいずれかしか取れないことを理解して、それに沿った呼び出しをする。

⑤ 非同期 tool (async)

import httpx

@mcp.tool()
async def fetch_url(url: str) -> str:
    """Fetch the content of a URL.

    Args:
        url: HTTP(S) URL to fetch

    Returns:
        Response body as text (max 50KB).
    """
    async with httpx.AsyncClient() as client:
        response = await client.get(url, timeout=10.0)
        return response.text[:50000]
async が使える: FastMCP は async 関数も認識。外部API呼び出し・DB問い合わせ等 I/O待ちが多い tool は async で書くべき。

⑦ エラーハンドリング

from mcp.server.fastmcp.exceptions import ToolError

@mcp.tool()
def divide(a: float, b: float) -> float:
    """Divide a by b.

    Raises:
        ToolError: when b is zero.
    """
    if b == 0:
        raise ToolError("Cannot divide by zero. Please provide a non-zero divisor.")
    return a / b
ToolError を投げる: Claude が「失敗した」と認識して、ユーザーに人間語で説明したり、別の方法を試せる。
普通のExceptionは: Claude には「内部エラー」とだけ伝わる → デバッグ困難。

⑧ tool 名・description の書き方

Claude にとっての「使いやすい tool」の条件:
  • name: 動詞_目的 形式 (例: get_weather, send_email, create_calendar_event)
  • description: 「いつ使うべきか」を明示
  • 引数説明: 例示を入れる (例: "Tokyo, New York")
  • 返り値説明: Claude が次のアクションを判断できる形

⑩ 完全なサーバー例 — Weather MCP

from mcp.server.fastmcp import FastMCP
import httpx

mcp = FastMCP("weather")
NWS_API = "https://api.weather.gov"

@mcp.tool()
async def get_forecast(latitude: float, longitude: float) -> str:
    """米国気象庁(NWS)から天気予報を取得する。

    Args:
        latitude: 緯度 (例: 40.7128 = NYC)
        longitude: 経度 (例: -74.0060 = NYC)

    Returns:
        次の5期間の天気予報テキスト
    """
    async with httpx.AsyncClient() as client:
        points = await client.get(f"{NWS_API}/points/{latitude},{longitude}")
        forecast_url = points.json()["properties"]["forecast"]
        forecast = await client.get(forecast_url)
        periods = forecast.json()["properties"]["periods"][:5]
        return "\n\n".join([
            f"{p['name']}: {p['detailedForecast']}" for p in periods
        ])

@mcp.tool()
async def get_alerts(state: str) -> str:
    """米国指定州の気象警報を取得する。

    Args:
        state: 2文字の州コード (例: "CA", "NY")

    Returns:
        現在発令中の警報一覧
    """
    async with httpx.AsyncClient() as client:
        response = await client.get(f"{NWS_API}/alerts?area={state}")
        alerts = response.json()["features"]
        if not alerts:
            return f"{state}州に現在の警報はありません"
        return "\n\n".join([
            f"[{a['properties']['severity']}] {a['properties']['headline']}"
            for a in alerts[:5]
        ])

if __name__ == "__main__":
    mcp.run(transport="stdio")
このコードだけで: Claude Desktop で「ニューヨークの天気予報教えて」と聞くと、Claude が自動で get_forecast(40.7128, -74.0060) を呼んで応答する。

⑪ tool 設計のベストプラクティス

原則1: 1 tool = 1責任 (Single Responsibility)

「天気取得 + 通知送信 + DB保存」を1つの tool にしない。3つに分ける → Claude が組合せ自由に。

原則2: idempotent (べき等) に設計

同じ引数で何度呼んでも同じ結果が返るように。Claude がリトライしても安全。
副作用 (DB更新等) は create_xxx / update_xxx と名前で明示。

原則3: トークン経済を意識

tool の返り値は Claude が読むトークン。長大なJSONを返すと context食う。「最大N件」「要約付き」等で制御。

原則4: エラーメッセージは人間語で

ToolError("API rate limit exceeded. Please retry in 60 seconds.") のように、Claude が次のアクションを判断できる 形で返す。

⑭ 理解度チェック

Q1. 関数を tool 化する最低限の作業は?

① @mcp.tool() デコレータを付ける ② 引数に型ヒント ③ docstring に説明
この3つで自動的に JSON schema が生成され、Claude が呼べる tool になる。

Q2. async 関数も tool 化できる?

できる。FastMCP は async 関数を認識して、await チェーンを管理してくれる。外部API呼び出し・DBアクセス等 I/O待ちが多い tool は async で書く。

Q3. ToolError と普通のException の違いは?

ToolError: Claude にエラーメッセージが伝わる → 次のアクション判断できる
Exception: Claude には「内部エラー」だけ → デバッグ困難
→ 業務ロジックエラーは ToolError、想定外バグは普通のException で分ける。

Q4. tool 設計の4原則は?

① 1 tool = 1責任 ② idempotent ③ トークン経済 ④ 人間語エラー
→ これを守ると Claude が組み合わせやすい・誤動作しにくい tool が作れる。
