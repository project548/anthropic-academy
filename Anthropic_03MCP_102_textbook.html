Accessing resources— クライアント側から MCP Resources を読む

Anthropic Academy / コース03 Model Context Protocol

① 前回 (#101) の続き

前回は server 側で resource を 定義 する方法を学んだ。今回は クライアント側 から、定義された resource を 呼び出して読む 方法を学ぶ。

核心: Resource は LLM が「自動で」呼ばない (tool と違って)。Host (アプリ) かユーザーが 明示的に context へ取り込む のが基本パターン。

② Resource アクセスの3ステップ

  1. 一覧取得: resources/list で公開中の resource を一覧
  2. テンプレ取得: resources/templates/list で動的 URI 一覧
  3. 読み込み: resources/read に URI を指定して中身を取得

③ MCP Client SDK での読み込み例

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    params = StdioServerParameters(command="python", args=["server.py"])

    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()

            # 1. 公開 resource 一覧
            resources = await session.list_resources()
            for r in resources.resources:
                print(r.uri, "-", r.name)

            # 2. 動的 URI テンプレ一覧
            templates = await session.list_resource_templates()

            # 3. 中身を読み込み
            result = await session.read_resource("docs://readme")
            for content in result.contents:
                print(content.text)  # str の場合
                # content.blob でバイナリ取得も可

④ Claude Desktop で resource を使う流れ

  1. Claude Desktop の入力欄で @ を入力
  2. サーバ名 + resource 一覧がサジェスト表示
  3. 選択するとその resource の中身がメッセージに添付される
  4. Claude はその文脈を理解して応答
例: ユーザーが @docs-server/readme を選ぶと、README.md 全文が prompt に挿入され、Claude はその内容について質問に答えられる。

⑤ Resource を context に含める3パターン

  • ユーザー指定: Claude Desktop で @ 経由 (上記)
  • 自動的に LLM 文脈へ: Host 側のロジックで初期 prompt に組込
  • tool 経由で間接アクセス: tool が内部で resource を read → 結果を返す

⑥ Subscribe (リアルタイム更新)

# resource の変更を購読する
await session.subscribe_resource("logs://errors")

# 更新通知 (notifications/resources/updated) が来る
async for notification in session.iter_notifications():
    if notification.method == "notifications/resources/updated":
        # 再読み込み
        new_data = await session.read_resource(notification.params.uri)

長期実行のアプリで「ログが追記されたら通知」のような動的監視に有用。

⑦ Resource vs Tool の使い分け再確認

  • 「読みたいデータ」がある → Resource (副作用なし)
  • 「実行したいアクション」がある → Tool (副作用あり)
  • 境界が微妙な場合 (例: 検索) → 副作用なら Tool / 単純検索なら Resource

⑧ 中学生向けに例えると

図書館で本を借りる流れ。① 目録 (resource list) を見る → ② 本棚から本を取る (read_resource) → ③ 中身を読む。「本を借りる」までは資料アクセス、「本に書き込む」のは tool (副作用) の世界。

⑨ 理解度チェック

Q1. Resource を読む3ステップは?

A. ① resources/list で一覧 → ② resources/templates/list で動的テンプレ → ③ resources/read で URI 指定して中身取得。

Q2. Claude Desktop で resource を context に入れる方法は?

A. 入力欄で @ を入力 → サーバ名 + resource をサジェストから選ぶ → 中身が prompt に挿入される。

Q3. Resource 変更をリアルタイムで知る方法は?

A. subscribe_resource() で購読 → notifications/resources/updated 通知を受け取る → 必要なら再 read。
