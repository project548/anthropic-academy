Multi-Turn conversations— 会話履歴を持たせるパターン

Anthropic Academy / コース02 Claude with the Anthropic API

① まず結論 — Claude API は無状態

Claude API は 毎リクエスト独立。前回の会話を覚えていない。会話履歴を持たせるには 毎回 messages に過去全部を入れて 送る必要がある。

これが分かれば全部わかる: 1ターン目だけ user。2ターン目以降は user → assistant → user → assistant... と交互に積む。

② 実装パターン

messages = []

def chat(user_msg):
    messages.append({"role": "user", "content": user_msg})

    response = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=1024,
        messages=messages
    )

    assistant_msg = response.content[0].text
    messages.append({"role": "assistant", "content": assistant_msg})
    return assistant_msg

chat("私の名前はアビです")
chat("私の名前は?")  # → "アビさんです" (履歴に基づく)
2回目の chat で Claude が「アビ」を覚えているのは、messages 配列に履歴が全部入っている から。

③ ロールの順番ルール

  • 最初は必ず user
  • その後 user / assistant が 交互
  • 連続して同じ role が来てはいけない
  • 最後は user で終わる (assistant 応答がこれから返ってくるので)

④ コンテキスト長の限界

会話を続けると messages がどんどん長くなる → 200K トークン (Opus 4.7 は 1M) 上限に達する。対策:

  • 古い履歴を要約して圧縮
  • 最新N件だけ保持 (スライディングウィンドウ)
  • 長期記憶を別DB (RAG) で管理

⑤ 中学生向けに例えると

Claude は記憶喪失の天才。毎回「これまでの会話メモ」を渡さないと前の話を覚えていない。あなたが「メモ係」になって、user/assistant 交互に書き積むのが multi-turn の本質。

⑥ 理解度チェック

Q1. Claude API は会話履歴を覚える?

覚えない (無状態)。毎リクエストごとに messages に全履歴を入れて送る必要がある。

Q2. ロール順番のルールは?

① 最初は user ② user/assistant 交互 ③ 連続同 role NG ④ 最後は user
