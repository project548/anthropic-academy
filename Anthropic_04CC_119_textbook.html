Module 5 ・ Lecture 119 ・ Hooks 概念

Introducing hooks— Claude Code の Hooks 機能とは何か?

Anthropic Academy / コース04 Claude Code

① Hooks とは?

Hooks = Claude Code が特定のイベント発生時に 自動でシェルコマンドを実行する仕組み。「Claude が tool を呼ぶ前」「ファイルを保存した後」「セッション終了時」など、決まったタイミングで自分のスクリプトを差し込める。

核心: Claude の動きを 自動的に拡張・制御 できる。例: 「Edit したら自動で prettier」「Bash の危険コマンドをブロック」「セッション終了時に Obsidian に保存」。

② 主な Hook イベント

イベント発火タイミング典型用途
PreToolUsetool 実行直前検証 / ブロック / 引数加工
PostToolUsetool 実行直後自動 format / 自動 lint
UserPromptSubmitユーザー入力直後プロンプト変換 / ログ
Stopセッション終了サマリー保存 / Obsidian 連携
SessionStartセッション開始初期化 / 環境変数読込

③ Hook で何ができる?

  • 自動 format: Write/Edit 後に prettier / black / gofmt 自動実行
  • 自動 lint: 変更ファイルに eslint / ruff 即実行
  • 危険コマンドブロック: rm -rf / を PreToolUse で拒否
  • 自動コミット: 一定時刻ごとに git commit (チェックポイント)
  • ログ保存: 全 prompt と response を外部 DB へ
  • 通知: 長時間タスク完了時にデスクトップ通知

④ Hooks vs Permissions

  • Permissions (settings.json): 「この tool は許可 / この Bash コマンドは禁止」の宣言型
  • Hooks: イベント時に 任意のスクリプトを実行する手続き型

Permissions = 静的ルール / Hooks = 動的ロジック。両方使い分け。

⑤ Hooks の置き場所

  • 個人グローバル: ~/.claude/settings.json の hooks セクション
  • プロジェクト共有: {project}/.claude/settings.json
  • 個人プロジェクト: {project}/.claude/settings.local.json (gitignore 推奨)

⑥ セキュリティ意識

Hook は強力な分、リスクも大きい:
  • 他人の settings.json を信用してインストールしない
  • Hook は あなたの端末で実行される (Claude 側ではない)
  • 悪意ある Hook で破壊操作も可能 → 中身を読まずに有効化しない
  • 機密情報を Hook 経由で外部送信しない

⑦ 中学生向けに例えると

家電の「自動運転」機能。エアコンに「人が部屋に入ったら自動で運転開始 (PreToolUse)」「30分経ったら自動で温度下げる (PostToolUse)」のようなルールを仕込んでおく感じ。Claude Code に対しても同じことができる。
