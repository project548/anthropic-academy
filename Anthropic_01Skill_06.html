スキルのトラブルシューティング
— 動かないとき、4パターンの原因と対処法

① 一言まとめ
スキルが動かないときの原因は「起動しない・読み込まれない・競合する・実行失敗」の4パターンにほぼ集約されます。ほとんどの問題はdescriptionの修正・ファイル配置の確認・優先度の確認・依存パッケージのインストールで解決できます。
② キーポイント
  • 1
    まず agent skills verifier を実行する
    UV でインストールしてスキルディレクトリで実行するか、任意の場所からコマンドを実行します。存在確認とバリデーションが一度にできます。
  • 2
    起動しない → descriptionを直す
    Claudeはセマンティックマッチングでスキルを選ぶため、リクエスト文とdescriptionの意味が重ならないとマッチしません。「Help me profile this」「Why is this slow?」など実際に使いそうなトリガーフレーズをdescriptionに追加し、バリエーションでテストします。
  • 3
    読み込まれない → パスとファイル名を確認する
    スキルは必ず「名前のディレクトリ/SKILL.md」という構造が必要です（skillsルート直下に置くのはNG）。ファイル名はSKILL（全大文字）.md（小文字）で完全一致。claude --debug でロードエラーを確認できます。
  • 4
    競合・上書きされる → 名前と優先度を確認する
    descriptionが似ていると間違ったスキルが起動します。より具体的な記述で差別化します。エンタープライズスキルと同名の個人スキルは必ず負けます。管理者に確認するか、スキル名を変えるのが現実的な対処です。
  • 5
    実行時エラー → 依存と権限を確認する
    外部パッケージを使うスキルはそのパッケージがインストール済みである必要があります（descriptionに明記も推奨）。スクリプトには実行権限が必要で、パスの区切り文字はWindows含め「/」（スラッシュ）を使います。

④ 用語集（小学生向け解説）
セマンティックマッチング
単語の完全一致ではなく「意味の近さ」でマッチングする仕組み。「速くして」と「パフォーマンス改善」が同じ意味と判断されます。
トリガーフレーズ
スキルを起動させる「合言葉」のような文章。descriptionにこれを書いておくとマッチしやすくなります。
agent skills verifier
スキルが正しく作られているかチェックするツール。文法ミスやファイル構造の問題を自動で見つけてくれます。
claude --debug
Claude Codeを詳細ログモードで起動するコマンド。スキルが読み込まれているかエラーが出ていないか確認できます。
実行権限（execute permission）
ファイルを「プログラムとして動かす」許可のこと。権限がないと「ファイルはあるのに動かない」状態になります。
キャッシュ
高速化のために保存された一時データ。古いキャッシュが残ると新しい設定が反映されないことがあります。
⑤ 1巡目 理解度チェック
Q
スキルのdescriptionに書くべき「トリガーフレーズ」とはどのようなものですか？
実際にユーザーが入力しそうな自然な表現です。例：「Help me profile this」「Why is this slow?」「Make this faster」など。Claudeはセマンティックマッチングでスキルを選ぶため、ユーザーの実際の言い回しに近い表現をdescriptionに入れることで起動率が上がります。バリエーションでテストして、起動しなかった表現をdescriptionに追加していくのが実践的な方法です。
Q
スキルが一覧（what skills are available）に出てこない場合、まず確認すべき2つのことは何ですか？
①ファイル配置の構造（スキル名のディレクトリ内にSKILL.mdがあるか、skillsルートに直置きしていないか）と、②ファイル名（SKILL.mdで大文字・小文字が正確か）の2点です。次に claude --debug を実行してロードエラーのログを確認します。
Q
個人で作った「code review」スキルがエンタープライズの「code review」スキルに常に負ける場合、どう対処しますか？
個人スキルの名前をより具体的なものに変えます（例：「frontend-code-review」など）。エンタープライズスキルは最高優先度を持つため同名では必ず上書きされます。管理者にエンタープライズスキルの内容を確認することもできますが、改名の方が即効性があります。
