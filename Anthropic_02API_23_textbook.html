A typical eval workflow— プロンプト評価の6ステップ反復プロセス

Anthropic Academy / コース02 Claude with the Anthropic API

① 全体像: 6ステップで何が起きるか

図① 6ステップの反復プロセス全体像

② ステップ別の中身

1初期プロンプトのドラフトを書く

最適化の出発点(ベースライン)を作る。例:

Please answer the user's question: {question}

とても素朴な書き方からスタートしてOK。これを改善していくのが目的。

2評価データセットを作る

テスト入力の集まり(3例〜数千例)。例:

  • 「2 + 2 はいくつ?」
  • 「オートミールはどう作る?」
  • 「月までの距離は?」

手書きでも、別の LLM に作らせてもOK。まずは3〜5問の少数から始めるのが現実的。

3プロンプトのバリエーションを作る

各データセット入力をプロンプトテンプレートに差し込んで、完成プロンプトを作る。

Please answer the user's question:
What's 2+2?

4Claude に応答を生成させる

各プロンプトを Claude に送って出力を集める。例:

  • 数学質問 → 「2 + 2 = 4」
  • オートミール質問 → 簡単な作り方を返す
  • 月質問 → 月までの距離を返す

5応答を採点する

グレーダー(採点機)で1〜10のスケールで点数化。10が満点。

図② グレーダーで採点 → ベースラインスコア

平均: (10 + 4 + 9) ÷ 3 = 7.66 → これがベースラインスコア。

6プロンプトを変えて、もう1周

ベースラインが取れたら、プロンプトを改善して全体を再実行。例:

Please answer the user's question:
{question}
Answer the question with ample detail

「ample detail (十分な詳細で)」を足してみる。

③ Before / After スコア比較

図③ プロンプト改善で 7.66 → 8.7 へ

客観的に分かること: 「ample detail」を足したことが効いて、平均スコアが +1.04 上がった。「なんとなく良くなった」ではなく 数値で改善を証明 できる。

④ 模試の例えで覚える

模試の例え評価ワークフロー
最初の答案テンプレを書くStep 1 (初期プロンプト)
練習問題集を用意するStep 2 (データセット)
テンプレで全問解くStep 3-4 (Claude 実行)
採点機で点数を出すStep 5 (採点)
テンプレを直して、また全問解いて点数比較Step 6 (反復)

これを何周もして「最高得点のテンプレ」を見つける。「なんとなく良い」を排除して、客観点数で実力を測るのがミソ。

⑥ 理解度チェック

Q1. 評価ワークフローのStep 1は何?

初期プロンプトのドラフトを書く(ベースラインを作る)。素朴な書き方からスタートしてOK。

Q2. データセットは最初から数千問用意しないとダメ?

違う。3〜5問の少数から始めて全然OK。手書きでも別のLLMに作らせてもOK。重要なのは「測れる」状態を早く作ること。

Q3. なぜ平均スコアを計算するの?

個別の応答スコアだとブレるが、平均すると プロンプト全体の性能 を1つの数値で表現できる。v1 vs v2 の比較がしやすくなる。

Q4. 「なんとなく良くなった気がする」が排除できる理由は?

客観点数(7.66 → 8.7 等)で改善幅が出るから。主観や思い込みではなく、数値が証拠になる。
