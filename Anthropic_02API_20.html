    応用1：Tool Use と組み合わせて厳密スキーマ
    pre-fill は手軽だがスキーマ検証は弱い。Tool Use の tool_choice = {"type":"tool","name":"..."} で強制ツール呼び出しすると、JSON Schema に沿った出力が保証される。信頼性最重視ならこちら。
  • 3
    応用2：Prompt Caching で繰り返し処理を高速化
    同じ tool schemas や system prompt を使い回す抽出処理は、cache_control: {"type":"ephemeral"} をtool/system に明示 → 1時間以内の同一入力は cache_read_input_tokens で返ってくる。コスト・レイテンシともに大幅削減。
    最低 1024 トークン以上 + 同一内容を1時間以内に再利用、で発火条件成立。

    応用3：Eval Pipeline で出力品質を自動評価
    構造化データ生成は出力の正確さが命。validate_json()（json.loads 試行）や validate_python()（AST parse 試行）でコードベース採点 → 10点 or 0点。Model-based grader と組み合わせて 平均スコアでプロンプト改善ループを回す。

    応用4：モデル選択と RAG / MCP との連携
    構造化データ抽出のモデル選択：Sonnet がバランス最適、大量バッチなら Haiku、複雑な抽出なら Opus。RAG で検索した chunk から構造化データを取り出すケースや、MCP server のツール出力として構造化データを返すケースでも、本テクニックが基盤になる。

④ 用語集（演習で覚える主要キーワード）
pre-fill
アシスタントメッセージの先頭を事前に埋め込むテクニック。Claude はその続きから生成するので、出力の方向を強くコントロールできる。
stop_sequences
指定した文字列が生成されたら即座に停止する仕組み。デリミタとセットで使い、余計な後続テキストを切り捨てる。
tool_choice
Tool Use 機能で特定ツール呼び出しを強制するパラメータ。{"type":"tool","name":"extract_user"} 形式。
Prompt Caching
入力処理の結果をキャッシュして再利用する仕組み。cache_control: ephemeral で有効化、1時間まで保持。
validate_json
出力が正しい JSON かどうか json.loads() で検証する関数。Eval pipeline の code-based grader で使う。
cache_read_input_tokens
キャッシュから読み出されたトークン数。レスポンス内で確認可能。普通の入力トークンより安く高速。
⑤ 理解度チェック
Q1
pre-fill + stop_sequences と Tool Use + tool_choice、どちらをいつ使うべきですか？
答えを見る
シンプル・スピード優先なら pre-fill。スキーマ厳密性・エラー耐性が必要なら Tool Use + tool_choice。Tool Use は JSON Schema が型を保証するため、本番運用ではこちらが推奨。pre-fill は試作・PoC・軽量タスク向き。
Q2
同じツールスキーマを使う構造化データ抽出を1日に1000回呼び出します。コスト最適化の手は？
答えを見る
Prompt Caching を有効化する。最後のツール schema に cache_control: {"type":"ephemeral"} を追加し、1時間以内の同一入力は cache_read_input_tokens として読み出される。最低1024トークンの内容が必要。さらにモデルを Haiku に切り替えれば速度・コストともに最適。
Q3
構造化データ抽出プロンプトの精度をどう測定し、どう改善ループを回しますか？
答えを見る
Eval Pipeline を組む：① テストデータセット作成 → ② 各テスト入力で出力生成 → ③ validate_json()（code grader）で構文検証10/0 + Model-based grader（質的評価1〜10）で内容スコアリング → ④ 平均点で評価 → ⑤ プロンプト改良 → 繰り返し。「Being Specific」で属性・ステップを足したり、「Providing Examples」で one-shot を追加すると点数が上がる。
