Environment inspection— Agent が「自分が居る環境」を理解するための仕組み

Anthropic Academy / コース02 Claude with the Anthropic API

① なぜ環境理解が重要?

Agent が自律的に tool を使うには、「今どこにいるか」「何が使えるか」「どんな状態か」 を最初に理解する必要がある。これが Environment inspection (環境観察)。

核心: Agent に最初に「環境を観察する tool」を使わせて状況把握 → その後、本タスクに入る。失敗率が大幅に下がる。

② 環境観察 tool の例

  • list_files: 現在ディレクトリのファイル一覧
  • get_cwd: 現在の作業ディレクトリ
  • git_status: git の状態 (ブランチ・変更ファイル)
  • list_env_vars: 環境変数
  • check_dependencies: インストール済みパッケージ
  • read_config: 設定ファイル (CLAUDE.md / package.json 等)

③ Claude Code での実装例

# Claude Code は標準で:
# 1. 起動時に Glob でプロジェクト構造把握
# 2. CLAUDE.md があれば Read
# 3. git status で状態確認
# 4. .gitignore / package.json / pyproject.toml をスキャン
# → 「このプロジェクトは Python/Node/Go か」「テストはあるか」を把握

# その後の指示はこの理解の上に乗る:
# ユーザー: "テスト追加して"
# Claude: (環境理解済みなので) "pytest があるね、tests/ に追加します"

④ 設計のコツ

  1. Agent の system prompt で「最初に環境を観察して」と明示
  2. 環境観察 tool は read-only / 副作用なし にする (失敗しても安全)
  3. 結果は キャッシュして何度も呼ばない (cost節約)
  4. 長時間 agent では 定期的に再観察 (環境変化に対応)

⑤ アンチパターン

  • 環境観察なし: いきなり実装 → Python/Node の違いを無視して動かない
  • 過剰観察: 全ファイル全ディレクトリを毎回スキャン → トークン浪費
  • 古い情報で動く: 初回観察結果をずっと使う → 環境変化に未対応

⑥ 中学生向けに例えると

新しい教室に行ったら、まず「教室の地図 (どこに何がある)」を見る。授業始める前に「教科書あるか」「机の場所」を確認する。それと同じことを agent もやる。

⑦ 理解度チェック

Q1. Environment inspection が必要な理由は?

A. Agent は環境状況を知らないと適切な tool を選べないため。先に観察してから本タスクに入ると失敗率が下がる。

Q2. 環境観察 tool に必須の性質は?

A. read-only / 副作用なし。観察自体が状態を壊すのを防ぐ。
