Module 2 ・ Lecture 111 ・ プロジェクト初期化

Project setup— Claude Code をプロジェクトで使う初期セットアップ

Anthropic Academy / コース04 Claude Code

① 既存プロジェクトでの開始

# 任意のディレクトリで claude を起動
cd ~/work/my-project
claude

# 初回起動時に Claude が以下を自動実行:
# - ls / Glob でプロジェクト構造を把握
# - package.json / pyproject.toml / Cargo.toml 等を読む
# - .gitignore を尊重
# - CLAUDE.md があれば必読

② CLAUDE.md の役割

プロジェクトルートに CLAUDE.md を置くと、Claude Code は毎セッションこれを 必読 する。プロジェクト固有のルール・規約・前提を伝える「Claude への手紙」。

記載すべき内容:
- プロジェクト概要 (何を作っているか)
- 主要コマンド (build / test / lint)
- コードスタイル (命名・フォルダ構成)
- やってほしくないこと (例: 本番DB触らない)
- 重要ファイルの場所

③ /init コマンドで自動生成

# Claude セッション内で
> /init

# → Claude がプロジェクトを分析して CLAUDE.md の雛形を作る
# 内容を確認して保存 → 次回以降のセッションで自動使用

④ ディレクトリ構成 (Claude Code 周り)

my-project/
├── CLAUDE.md              # プロジェクト固有ルール (必読)
├── .claude/
│   ├── settings.json      # プロジェクト設定 (hooks/permissions)
│   ├── settings.local.json # 個人ローカル設定 (gitignore推奨)
│   ├── commands/          # プロジェクト専用 slash commands
│   │   ├── deploy.md
│   │   └── review.md
│   └── agents/            # プロジェクト専用サブエージェント
└── ... (実コード)

⑤ 設定の階層 (上書きルール)

  1. ユーザー指定 (起動時引数 / セッション中の指示)
  2. プロジェクト .claude/settings.local.json
  3. プロジェクト .claude/settings.json
  4. プロジェクト CLAUDE.md
  5. グローバル ~/.claude/settings.json
  6. グローバル ~/.claude/CLAUDE.md

下位ほど一般的・上位ほど具体的。具体的な設定が優先。

⑥ よくある初期セットアップ手順

  1. プロジェクトに移動 → claude 起動
  2. /init で CLAUDE.md 自動生成
  3. 生成内容を確認・追記 (やってほしくないこと等)
  4. 必要なら .claude/settings.json に hooks / permissions 設定
  5. .gitignore に .claude/settings.local.json 追加
  6. 動作確認: 「このプロジェクトの概要は?」

⑦ 中学生向けに例えると

新しいバイト先で先輩から「うちのお店のルール」のメモを渡される感じ。CLAUDE.md = そのルールメモ。これがあるおかげで毎日聞かなくても、Claude が自分でルールを思い出せる。
