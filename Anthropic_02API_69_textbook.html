The server inspector— MCP Inspector でローカルサーバーをデバッグ・テストする

Anthropic Academy / コース02 Claude with the Anthropic API

① まず結論 — Inspector って何?

MCP Inspector は ブラウザベースのデバッグ&テストUI。Claude Desktop に登録する前に、自作 MCP サーバーが正しく動くか確認できる開発者ツール。

できること:
  • tool / resource / prompt の一覧確認
  • tool を任意の引数で呼び出して結果確認
  • 送受信される JSON-RPC メッセージのログ
  • エラー再現・デバッグ
  • capability negotiation の中身観察

② なぜ Inspector が必要?

Claude Desktop で直接テストInspector でテスト
毎回 Claude Desktop 再起動コード変更 → そのままリロード
Claude が tool 呼ぶか分からないUI から任意引数で 強制実行
ログが見えないJSON-RPC 通信を可視化
エラー時のメッセージが不明stderr / traceback が見える
1イテレーション 30秒1イテレーション 5秒
開発サイクル: Inspector で開発・デバッグ → 動作確認できたら Claude Desktop に登録 → 本番運用、という流れ。

③ 起動方法 — 1コマンド

# プロジェクトディレクトリで
uv run mcp dev main.py

# 出力例:
# MCP Inspector starting...
# Server connected. Click here to inspect:
#   http://localhost:5173?MCP_PROXY_AUTH_TOKEN=xxx
1コマンドで完結: mcp dev は内部で:
  1. あなたの MCP サーバー (main.py) を子プロセス起動
  2. Inspector Web UI を localhost:5173 で起動
  3. 両者を MCP プロトコルで接続
ブラウザで URL を開けば即操作可能。

UIパネル表示内容

魔法: Inspector が JSON schema を読んで 適切な入力フォーム を自動生成。string なら text input、int なら number input、Literal なら dropdown、boolean なら checkbox 等。

⑥ History パネルで JSON-RPC を観察

# 1. Client → Server: initialize リクエスト
{ "jsonrpc": "2.0", "id": 1, "method": "initialize", ... }

# 2. Server → Client: initialize レスポンス
{ "jsonrpc": "2.0", "id": 1, "result": {
    "protocolVersion": "2025-06-18",
    "capabilities": { "tools": {...}, "resources": {...} },
    "serverInfo": { "name": "weather", "version": "0.1.0" }
}}

# 3. Client → Server: tools/list
{ "jsonrpc": "2.0", "id": 2, "method": "tools/list" }

# 4. Server → Client: tool 一覧
{ "jsonrpc": "2.0", "id": 2,
  "result": { "tools": [{"name": "get_weather", ...}] } }

# 5. Client → Server: tools/call
{ "jsonrpc": "2.0", "id": 3, "method": "tools/call",
  "params": { "name": "get_weather", "arguments": {"city": "Tokyo"} } }

# 6. Server → Client: 実行結果
{ "jsonrpc": "2.0", "id": 3, "result": {...} }
学習価値: MCP プロトコルの実体験。「Claude Desktop の中で何が起きてるか」がブラックボックスでなくなる。

⑦ 開発フロー — Inspector を活用する

# 1. Inspector 起動 (ターミナル 1)
uv run mcp dev main.py
# → ブラウザで Inspector UI 開く

# 2. main.py を編集 (エディタ) → 新しい tool を追加

# 3. Inspector で Reload (ボタン1つ)
# → サーバー再起動 + tools/list 自動更新

# 4. Tools パネルで新 tool を実行 → 即動作確認

# 5. Server Logs パネルでログ確認 → エラーあれば修正

# (3〜5 を繰り返す。1イテレーション 5秒)

# 動いたら Claude Desktop config に登録 → 本番運用

⑧ よくあるトラブルと Inspector での確認

1. tool が一覧に出ない

Inspector の確認方法: Tools パネルが空 → main.py で @mcp.tool() 付け忘れ or import エラー。
→ Server Logs パネルで traceback 確認 → 修正 → Reload。

2. tool 実行で「Invalid parameters」

Inspector の確認方法: tool のスキーマを見て、引数の 型 を確認。
例: city: str なのに数値入力 → エラー。type hints を再確認。

3. tool 実行で内部エラー (500)

Inspector の確認方法: History に error response が記録される + Server Logs に stderr 出力 + traceback。
→ Python例外をキャッチして ToolError に変換するべき。

4. capability negotiation が失敗

Inspector の確認方法: Connection パネルで「initialize」 が赤くなる。
→ protocolVersion 不整合・serverInfo 必須項目欠落等を疑う。

⑨ Inspector 単独起動 (任意サーバー接続)

# 既存の (例: GitHub MCP server) に接続してテスト
npx @modelcontextprotocol/inspector npx -y @modelcontextprotocol/server-github

# あるいは HTTP リモート MCP に接続
npx @modelcontextprotocol/inspector --url https://slack-mcp.example.com/mcp
応用: 自分のサーバーだけでなく、他人のMCPサーバーをテストする 用途にも使える。サードパーティMCPを評価するときに重宝。

⑩ セキュリティ注意

Inspector はローカル開発用:
  • localhost にしか bind しない (デフォルト)
  • MCP_PROXY_AUTH_TOKEN でアクセス制限
  • 本番環境では絶対起動しない (機密データに触れるサーバーの場合は特に)
  • 共有ネットワーク (カフェ Wi-Fi 等) では 外部公開設定にしない

⑪ resource / prompt も同様に検査

# Resources パネル
# → resources/list の結果が一覧表示
# → 個別 resource クリックで resources/read 実行
# → URI と content をプレビュー

# Prompts パネル
# → prompts/list の結果
# → prompt をクリックで prompts/get 実行
# → 動的補完されたプロンプトテキストを確認
3本柱を一気に検査: tool だけでなく resource / prompt も同じUIで動作確認できる。MCP サーバー丸ごとデバッグ。

⑭ 理解度チェック

Q1. Inspector の用途は?

自作 MCP サーバーを Claude Desktop に登録する前に デバッグ・テストすること。tool 単体実行・JSON-RPC ログ確認・schema検査・サーバーログ閲覧 を一画面でできる。

Q2. どう起動する?

uv run mcp dev main.py 一発。サーバーとInspector UI を両方起動 → ブラウザで localhost:5173 を開く。

Q3. Inspector で確認すべき4点は?

① Tools パネル: tool一覧と schema
② tool 実行: 任意引数で結果確認
③ History: JSON-RPC 通信ログ
④ Server Logs: stderr / traceback

Q4. セキュリティ上の注意は?

Inspector は ローカル開発用。① localhost のみ ② AUTH_TOKEN で制限 ③ 本番環境では絶対起動しない ④ 共有ネットワークで外部公開しない
