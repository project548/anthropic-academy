Agents and workflows— エージェントとワークフローの定義・違い・選び方

Anthropic Academy / コース02 Claude with the Anthropic API

① 結論 — 2つは別物

Anthropic 公式の定義 (2025年4月「Building effective agents」):

  • Workflow: 事前に決められた経路 で LLM とtool を組合せて動かす (決定論的)
  • Agent: LLM が動的に次のアクションを判断して動く (非決定論的・自律的)
核心: 「使う前に流れが決まってる」= workflow / 「使いながら流れを決める」= agent。

② 比較表

観点WorkflowAgent
制御フロー固定 (人間が設計)動的 (LLMが判断)
予測可能性高い・デバッグ容易低い・テスト難しい
柔軟性低い (パターン固定)高い (未知タスク対応)
コスト低い (必要な分のみ)高い (試行錯誤)
適する場面業務自動化・既知タスク未知タスク・探索系

③ 選び方の判断軸

  1. タスクの流れが事前に分かる → workflow
  2. ユーザー要望が毎回違う・未知 → agent
  3. 失敗時のコストが大きい → workflow (予測可能)
  4. 探索・調査タスク → agent
  5. 本番運用・SLA厳しい → workflow
Anthropic 推奨: まず workflow で実装 → 動的判断が必要な部分だけ agent 化。最初から全部 agent 化は過剰設計になりがち。

④ Workflow の5パターン (#83-#85 で詳述)

  • Parallelization (#83): 独立タスクを並列実行
  • Chaining (#84): タスクを連鎖して逐次実行
  • Routing (#85): 入力に応じて分岐先選択
  • Orchestrator-workers: マスターが子タスクに分割
  • Evaluator-optimizer: 生成 → 評価 → 改善ループ

⑤ 中学生向けに例えると

Workflow = レシピ通りに料理。手順1→2→3→完成。
Agent = 自由料理。冷蔵庫見て「今日はカレー」「いや、肉じゃが」と臨機応変。
