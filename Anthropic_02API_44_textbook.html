② run_tools — 複数 tool_use を変換

def run_tools(message):
    tool_requests = [b for b in message.content if b.type == "tool_use"]
    tool_result_blocks = []

    for tool_request in tool_requests:
        try:
            tool_output = run_tool(tool_request.name, tool_request.input)
            tool_result_block = {
                "type": "tool_result",
                "tool_use_id": tool_request.id,
                "content": json.dumps(tool_output),
                "is_error": False
            }
        except Exception as e:
            tool_result_block = {
                "type": "tool_result",
                "tool_use_id": tool_request.id,
                "content": f"Error: {e}",
                "is_error": True
            }
        tool_result_blocks.append(tool_result_block)

    return tool_result_blocks

ポイント:

  • message.content から tool_use ブロックだけを抜き出す
  • 各々を try/except で実行 — 成功時は結果、失敗時はエラー文を block 化
  • 失敗時も tool_result を返す(返さないと Claude が困惑して固まる)
  • 戻り値は 複数 tool_result の配列
is_error=True 設計の妙: 「失敗を Claude に伝えて、別の手を考えてもらう」発想。沈黙より失敗共有のほうが安全。

④ run_conversation — 核心のループ

def run_conversation(messages):
    while True:
        response = chat(messages, tools=[get_current_datetime_schema])
        add_assistant_message(messages, response)
        print(text_from_message(response))

        if response.stop_reason != "tool_use":
            break  # ← Claude がもう tool 要らないと判断したら抜ける

        tool_results = run_tools(response)
        add_user_message(messages, tool_results)

    return messages

図① run_conversation の5ステップループ

⑤ stop_reason の意味と使い方

stop_reason意味ループ
"end_turn"Claude が自然に終わった(最終応答)break(終了)
"max_tokens"トークン上限に達したbreak(終了)
"tool_use"tool を呼びたいので止めた継続
"stop_sequence"指定 stop sequence にヒットbreak(終了)
ループ継続の条件は stop_reason == "tool_use" のみ。それ以外は break して終了。シンプルだけど強力な設計。

ポイント: 1つの質問に2つの情報が必要なとき、Claude は 自動的に2回 tool_use をループ。

  • 1ターン目: Claude が %H:%M で要請 → サーバーが "11:16" を返す
  • 2ターン目: Claude が %S で要請 → サーバーが "30" を返す
  • 3ターン目: Claude が両方を組み合わせて最終応答(stop_reason="end_turn")
これが multi-turn tool conversation の本質。「Claude が必要なだけ道具を借り、最後にまとめて答える」自動推論システム。

⑫ 理解度チェック

Q1. run_conversation ループはいつ抜ける?

response.stop_reason != "tool_use" のとき。具体的には "end_turn"(自然終了)・"max_tokens"(上限)・"stop_sequence"(指定文字ヒット)のいずれか。Claude が「もう道具要らない」と判断したサイン。

Q2. なぜ try/except で囲むの?

ツール関数が失敗(ValueError 等)しても Claude に結果を返さなければループが止まる から。失敗時は is_error: True + エラー文を tool_result に入れることで、Claude が読んで自己修復できる。

Q3. 1回の質問で Claude が複数の tool を呼ぶ典型例は?

「HH:MM と SS の両方欲しい」のように、1つの質問に複数の情報が必要 な場合。Claude は1ターン目で1個目を要請 → 結果受け取り → 2ターン目で2個目を要請 → 結果受け取り → 3ターン目で統合応答、というループを自動でこなす。
