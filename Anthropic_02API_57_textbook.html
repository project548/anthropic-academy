Image input— Claudeに画像を見せて、視覚情報から答えてもらう

Anthropic Academy / コース02 Claude with the Anthropic API

① まず結論 — 画像入力って何?

Claude は マルチモーダル — テキストだけでなく画像も入力として受け取れる。スクショ・写真・図表・手書きメモ・OCR元の文書を「見せる」と、それを理解して答える。

対応モデル: Claude 3 Haiku 以降のすべてのモデル
対応形式: JPEG / PNG / GIF / WebP
サイズ上限: 5MB / 画像 (base64エンコード後 8MB)

② 2つの渡し方 — base64 と URL

方式長所短所
base64ローカル画像をそのまま送れる大きい・トークン多い
URLシンプル・小さい公開URLが必要

③ 最小コード — base64で画像を渡す

import base64
import anthropic

client = anthropic.Anthropic()

with open("./photo.jpg", "rb") as f:
    image_data = base64.standard_b64encode(f.read()).decode("utf-8")

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    messages=[{
        "role": "user",
        "content": [
            {"type": "image", "source": {"type": "base64", "media_type": "image/jpeg", "data": image_data}},
            {"type": "text", "text": "この写真に何が写っているか説明してください"}
        ],
    }],
)

print(response.content[0].text)
注目: content が リスト になっている。複数のブロック (image + text) を混ぜて1メッセージにできる。

④ URL方式 (推奨・シンプル)

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    messages=[{
        "role": "user",
        "content": [
            {"type": "image", "source": {"type": "url", "url": "https://example.com/photo.jpg"}},
            {"type": "text", "text": "この画像の感情は?"}
        ],
    }],
)
URL方式の制約: 公開URL必須・httpsのみ・Anthropic が取得できる必要あり。機密画像なら base64 一択。

⑤ 用途別ベストプラクティス

用途プロンプト例 + コツ
OCR (文字読取)「画像内の全テキストをそのまま書き出して」
表データ抽出「表をMarkdownテーブルで再現して」
UIスクショ分析「このUIに改善点を5つ提案して」
図解・チャート理解「このグラフから読み取れる傾向は?」
手書きメモ書き起こし「この手書きノートをテキスト化して」

⑥ 複数画像を一度に渡す

content_blocks = []
for image_path in ["before.jpg", "after.jpg"]:
    with open(image_path, "rb") as f:
        data = base64.standard_b64encode(f.read()).decode("utf-8")
    content_blocks.append({
        "type": "image",
        "source": {"type": "base64", "media_type": "image/jpeg", "data": data}
    })

content_blocks.append({"type": "text", "text": "Before と After の違いを箇条書きで"})

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=2048,
    messages=[{"role": "user", "content": content_blocks}]
)
応用: 比較分析・連続写真の動き解析・スライド全枚数読み込み等。
上限: 1リクエストあたり 100枚。

⑦ コスト計算

画像も input tokens としてカウントされる。サイズで決まる:

tokens = (width_px * height_px) / 750

# 例:
# 1024 × 1024 ピクセル → 約 1,400 tokens
# 1920 × 1080 ピクセル → 約 2,765 tokens
# 標準写真 (3000 × 2000) → 約 8,000 tokens
節約テク:
  • 解像度を 1568px 以下 に縮小してから送る
  • JPEG (圧縮率高) を選ぶ
  • Claude が必要としない領域はトリミング

⑧ 失敗パターン

「画像が読めない」エラー

① media_type 間違い ② base64エンコード前の生バイナリを送ってしまった ③ 5MB超え → 元画像のサイズ・形式を確認

Claude が画像内容を間違える

① 画像解像度が低すぎる ② プロンプトが曖昧 (「これ何?」より「テキストを全部抽出して」が明確) → 高解像度版で再試行 + プロンプト具体化

URL方式で取得失敗

① URL が非公開 ② robots.txt で禁止 ③ Cookie認証必要なページ → base64方式に切り替え

⑨ 中学生向けに例えると

学校の例えimage input の対応
「先生、この写真見て」と差し出すtype="image" の content block
「これ何が写ってる?」と聞くtype="text" の質問
写真を見ながら先生が説明するClaude の応答
「Before と After 並べて違い教えて」複数画像
核心: テキストでは伝えにくい情報 (図・写真・表・UI) を そのまま見せて聞ける。説明する手間が消える。

⑪ 理解度チェック

Q1. 画像入力で base64 と URL の使い分けは?

base64: ローカル画像・機密画像 / コードが少し複雑
URL: 公開画像 (Wikipedia 等) / コードがシンプル

Q2. 画像のトークン消費の計算式は?

(width × height) / 750 = トークン数。1024×1024 ≈ 1,400 トークン。大きい画像はコスト増 → 1568px以下にリサイズ推奨。

Q3. 複数画像を渡せる?

はい、1リクエストあたり 最大100枚。content に複数の type="image" ブロックを並べる。

Q4. どんな用途で強い?

OCR (文字読取)・表データ抽出・UIスクショ分析・図解理解・手書きノート書き起こし。「テキストで書くのが面倒なものを、見せて聞く」に強い。
