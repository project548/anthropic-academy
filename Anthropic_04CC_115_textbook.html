Controlling context— 長いセッションで context を上手く管理する

Anthropic Academy / コース04 Claude Code

① なぜ context 管理が大事?

Claude には context window 上限 がある (Opus 4.7 = 1M トークン、Sonnet 4.6 = 200K)。大規模プロジェクトや長セッションでは 不要な情報を入れない・古い情報を整理する 工夫が必要。

核心: Context が膨らみすぎると、Claude の精度低下 / コスト増 / latency 増 のトリプルパンチ。意図的に制御する。

② context を圧縮する3つの方法

  1. /compact: 過去のやり取りを Claude 自身が要約 → 履歴の代わりに圧縮版を保持
  2. /clear: 履歴を完全クリア (新しいセッションと同じ状態に)
  3. 新セッション開始: ターミナル再起動 → 完全リフレッシュ

③ /compact の使い方

# 長いセッションで context が膨らんだら
> /compact

# → Claude が過去履歴を要約してくれる
# → 重要な決定事項・現在の状態は保持
# → 一時的な情報・解決済みエラーは破棄

Claude Code は自動 compaction も搭載。context 残量が少なくなったら自動で発動。

④ Context を肥大化させないコツ

  • 大ファイルを丸ごと読ませない: 必要な範囲を file.ts:42-80 と指定
  • 確定した話題は CLAUDE.md / KNOWLEDGE.md に逃がす: 揮発性 → 永続化
  • 巨大ログを貼らない: head -100 や grep で絞る
  • session を作業単位で分ける: 「テスト作業」「lint対応」を別セッション
  • 不要な過去履歴は /compact

⑤ Subagent / Agent tool で分離

並列で動かしたい調査タスクは サブエージェント を呼ぶと、メイン context を汚さずに完了できる。

# 大量検索を別エージェントに委譲
> Explore agent で「TODO コメントを全部リストアップして」

# → サブエージェントが探索 → 結果サマリーだけメインに戻る
# → 何百ファイル読んでも main context は汚れない

⑥ Context 残量を意識する

  • セッション開始から残量 ~80% までは「自由に動く」
  • ~50% で「集中作業のみ」
  • ~20% で「/compact 推奨」
  • 残量赤表示で「/compact 必須 or 新セッション」

⑦ 中学生向けに例えると

勉強机の上が散らかってきたら整理する作業。/compact = 必要なメモだけ残して他は片付ける / /clear = 机の上全部リセット / 新セッション = 別の部屋に移動。机が広いほど集中しやすい。
