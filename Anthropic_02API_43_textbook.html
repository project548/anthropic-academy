② add_user_message を柔軟化

from anthropic.types import Message

def add_user_message(messages, message):
    user_message = {
        "role": "user",
        "content": message.content if isinstance(message, Message) else message
    }
    messages.append(user_message)

ポイント:

  • isinstance(message, Message) で Anthropic SDK の Message オブジェクトかどうか判定
  • Message ならその .content を取り出す(text + tool_use のリスト)
  • str や list ならそのまま使う
入力処理
str("こんにちは")そのまま content に入る
list([tool_result, ...])そのまま content に入る(ツール結果用)
Message オブジェクト.content を抜き出して content に入る
add_assistant_message も同じ仕組み(コードは省略)。両方とも「3パターン対応」になる。

③ chat 関数を tool 対応に

def chat(messages, system=None, temperature=1.0, stop_sequences=[], tools=None):
    params = {
        "model": model,
        "max_tokens": 1000,
        "messages": messages,
        "temperature": temperature,
        "stop_sequences": stop_sequences,
    }
    if tools:
        params["tools"] = tools
    if system:
        params["system"] = system
    message = client.messages.create(**params)
    return message  # ← Message 全体を返す

変更点:

  • tools=None デフォルト引数を追加 → tool 使うときだけスキーマを渡せる
  • return message で Message オブジェクト全体 を返す(text だけ抜き出さない)
  • 呼び出し側で必要なら text_from_message で抜き出す
Why Message 全体? tool_use ブロックも保持しないと、後でループ内で stop_reason や tool 要請内容を取り出せない。

④ text_from_message ヘルパー

def text_from_message(message):
    return "\n".join(
        [block.text for block in message.content if block.type == "text"]
    )

Message の中の text ブロックだけ を抽出して結合。tool_use ブロックは無視。「人間に見せる用」の文字列が必要なときだけ呼ぶ。

使う場面使う関数
print して人間に見せるtext_from_message(msg)
履歴に追加する(後でループで再利用)add_assistant_message(messages, msg) (Message 丸ごと)
tool 要請を取り出す[b for b in msg.content if b.type == "tool_use"]

⑨ 理解度チェック

Q1. なぜ add_user_message を更新する必要があるの?

tool use を有効にすると、user メッセージに tool_result ブロックのリスト を入れることがある。これまでの「str しか受け入れない」前提のままだとループが組めない。str / list / Message 全部受け入れるよう柔軟化する。

Q2. chat 関数を「Message 全体を返す」ように変えたのはなぜ?

tool_use ブロックや stop_reason 等の情報を後で使うため。text だけ返すと、Claude が「ツールを呼びたい」と要請しても、その情報が捨てられてループが組めない。Message 全体を返して、必要な情報を呼び出し側で取り出す。

Q3. text_from_message はどんな時に使う?

「Claude の最終応答を人間に見せたい」とき。Message オブジェクトのまま print してもダメで、text ブロックだけ抜き出して文字列にする必要がある。tool_use ブロックは無視される設計。

Q4. tools=None をデフォルト引数にしたメリットは?

tool を使わないシンプルな呼び出し(普通のチャット)と、tool を使う呼び出しを 同じ chat 関数で扱える。tools を渡さなければこれまでと同じ動作、渡せば tool use 対応になる。後方互換性を保ちつつ機能拡張。
