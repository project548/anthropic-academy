Module 9 ・ Lecture 37

Introducing tool use— Claude を外の世界とつなぐ「ツール使用」入門

Anthropic Academy / コース02 Claude with the Anthropic API

① ツールなし Claude の限界

Claude は学校でいう「すごく物知りな子」だけど、知っているのは 学習時に読んだ本 だけ。今日の天気、今日のニュース、自社の DB の中身は そのままでは知らない。

図① ツールなし(左：古い本だけで答える) vs ツールあり(右：外の世界に手を伸ばせる)

核心: Tool use(ツール使用) は Claude を「静的な知識ベース」から「ライブデータを扱える動的アシスタント」に変える仕組み。

② Tool use とは何か

Tool use(ツール使用) = Claude が 訓練データの範囲を超えて、外部の情報やシステムにアクセスする手段。

「使っていいツール一覧」をプロンプトと一緒に渡しておくと、Claude が必要に応じて「これ使わせて」と要求できるようになる。

イメージ: Claude に「電卓」「天気 API」「社内 DB」「メール送信機能」 などの道具箱を渡しておく。質問の内容に応じて、Claude が自分で「天気 API 使うね」と選んで呼び出す。

③ 4ステップの往復フロー

Tool use は 明確な往復(back-and-forth) のパターンで動く。一度の API 呼び出しでは終わらず、Claude とサーバーの間で 会話のキャッチボール が起きる。

図② Tool use の4ステップ往復フロー

④ 天気の具体例で追いかける

ステップやりとり
Step 1ユーザー: 「SF の天気は?」 → アプリが Claude へ送信(tool 説明込み)
Step 2Claude: 「get_weather(location="San Francisco") を呼んで」と tool 要請 を返す
Step 3サーバー: weather API を実行 → 「曇り 15℃」を取得
Step 4サーバー → Claude: 「データ: 曇り 15℃」 → Claude: 「SF は現在曇りで15℃です」
 
# Step 2 で Claude が返す「tool 要請」のイメージ
{
  "type": "tool_use",
  "id": "toolu_01A...",
  "name": "get_weather",
  "input": { "location": "San Francisco" }
}

# Step 4 でサーバーが返す「tool 結果」のイメージ
{
  "type": "tool_result",
  "tool_use_id": "toolu_01A...",
  "content": "曇り, 15℃"
}

このフォーマットの詳細は次以降のレクチャー(#40 Tool schemas / #41 Handling message blocks / #42 Sending tool results)で深掘りする。今は 「往復で会話する」 という感覚だけ掴めればOK。

⑤ なぜ嬉しいのか(主な利点)

利点説明
リアルタイム情報訓練データ以後の新しい情報にアクセスできる(今日の天気・最新ニュース・株価)
外部システム連携DB・API・社内システム・他サービスと接続して情報を引っ張れる
動的応答古い知識ではなく、今この瞬間のデータで答えられる

⑦ キーワード一覧

英語読み方意味

⑧ 理解度チェック

Q1. ツールなし Claude の最大の問題点は何?

訓練データの知識しか持っていないので、今この瞬間のデータ(現在の天気・最新ニュース・社内 DB の中身)にアクセスできないこと。「分かりません」としか答えられない場面が多発する。

Q2. Tool use の4ステップを順番に言える?

Step 1. 初期リクエスト(ユーザー質問 + 使ってよい道具一覧を Claude に送る)
Step 2. Tool 要請(Claude が「この道具を使いたい」と要求)
Step 3. データ取得(サーバーが実際に道具を実行 → 結果を取得)
Step 4. 最終応答(サーバーが結果を Claude に返送 → Claude が最終回答を生成)

Q3. Step 2 と Step 3 の違いは?

Step 2 は Claude が「呼んでください」と要請する だけで、実際にはまだ API を叩いていない。Step 3 で サーバー側のコードが本当に外部 API/DB を実行 する。Claude は自分でネットには出ない(出さない設計)。

Q4. なぜ「構造化インタラクション」が利点なの?

Claude が「何が欲しいか」を tool_use ブロックという 決まった形式で明示する ので、サーバー側のコードは「どの関数をどの引数で呼ぶか」が機械的に判断できる。自然文を毎回パースするより遥かに安全で確実。
