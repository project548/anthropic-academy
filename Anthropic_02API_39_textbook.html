Tool functions— Claude に渡す「道具」を Python 関数で作る

Anthropic Academy / コース02 Claude with the Anthropic API

① Tool function とは何か

Tool function = Python の普通の関数。Claude が「これ呼びたい」と判断したら、サーバー側で自動的に実行される。

例: ユーザー「今何時?」 → Claude「get_current_datetime 呼んで」と要請 → サーバーが関数実行 → 現在時刻を Claude に返す → Claude が自然言語で回答。

つまり Tool function は Claude の手足。Claude 自身は計算もネット接続もしないが、関数を 「呼んで」 と指示することで結果を間接的に取りに行ける。

② Tool function 設計の3原則

図① Tool function 設計の3原則

Why 検証が大事? Claude はエラーメッセージから学習する。"location cannot be empty" と返せば、Claude は 正しい値で再試行 する。逆に「ERROR」だけだと Claude は何が悪いか分からない。

③ 最初のツール関数を書いてみる

from datetime import datetime

def get_current_datetime(date_format="%Y-%m-%d %H:%M:%S"):
    if not date_format:
        raise ValueError("date_format cannot be empty")
    return datetime.now().strftime(date_format)

3つの原則を全部満たしている:

  • 名前: get_current_datetime — 「現在の日時を取得」と一目で分かる
  • 検証: if not date_format: で空文字を弾く
  • エラー文: "date_format cannot be empty" — Claude が読んで何をすべきか分かる
# 使い方
get_current_datetime()
# → "2024-01-15 14:30:25"

get_current_datetime("%H:%M")
# → "14:30"

get_current_datetime("")
# → ValueError: date_format cannot be empty

⑧ 理解度チェック

Q1. Tool function は普通の Python 関数と何が違う?

基本は同じ。違いは「Claude が読む前提で書く」という点。わかりやすい名前・入力検証・親切なエラーメッセージ の3点を意識して書くことで、Claude が安全に呼んで、エラー時には再試行できる関数になる。

Q2. なぜ「エラーメッセージを具体的に書く」ことが大事?

Claude もエラーメッセージを 読んで学習 する。"location cannot be empty" と返せば、Claude は location を埋めて再試行できる。逆に「ERROR」だけだと、Claude は何を直せばいいか分からず諦める。

Q3. 検証で raise ValueError を使う理由は?

① Claude も Python の例外を介してエラー内容を読める ② 「想定外の値が来た」と 明示的に 知らせる ③ 後で type checker やテストが見つけやすくなる。return None で済ますのは NG(Claude が「成功した」と勘違いする)。

Q4. get_current_datetime の引数 date_format はなぜデフォルト値付きなの?

Claude が「書式の指定なし」で呼んだときも動かすため。デフォルト "%Y-%m-%d %H:%M:%S" を入れておけば、Claude が get_current_datetime() で呼んでもエラーにならず、標準書式の文字列が返る。柔軟性のための設計。
