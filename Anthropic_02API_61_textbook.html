Files API— ファイルを事前アップロードして message に何度も参照させる

Anthropic Academy / コース02 Claude with the Anthropic API

① まず結論 — Files API って何?

ファイルを Anthropic サーバーに 1回だけアップロード し、file_id を発行。以降の messages.create では「base64 を毎回送る」代わりに file_id を参照 するだけでよい。

クイズ問題の答えはこれ: "Uploading files ahead of time and referencing them later instead of encoding them directly in messages"

② 何が嬉しい? — base64 直貼りとの違い

観点base64直貼り (旧)Files API (新)
1回目のリクエスト巨大なbase64文字列を含むfile_id だけ参照 (短い)
2回目以降毎回base64を再送信同じ file_id を再利用
ネットワーク都度大量転送1回だけ転送
レイテンシ大ファイルでは遅い低レイテンシ
同一ファイル複数質問毎回課金1回だけ + cache連携で90%OFF
適する場面:
  • 同じPDF/画像について 複数回質問 するチャットbot
  • 巨大ファイル (30MB の PDF 等)
  • マルチターン会話で同じ参考資料を毎回参照
  • Batch API で同じファイルを大量処理

③ 使い方 — 3ステップ

# STEP 1: ファイルをアップロード (1回だけ)
import anthropic

client = anthropic.Anthropic()

file_obj = client.beta.files.upload(
    file=("report.pdf", open("./report.pdf", "rb"), "application/pdf"),
)
file_id = file_obj.id  # 例: "file_01ABC..." (永続)

# STEP 2: メッセージ作成時に file_id で参照
response = client.beta.messages.create(
    model="claude-opus-4-7",
    max_tokens=2048,
    messages=[{
        "role": "user",
        "content": [
            {
                "type": "document",
                "source": {
                    "type": "file",
                    "file_id": file_id  # ← ここ!
                }
            },
            {"type": "text", "text": "このPDFの要約を5項目で"}
        ],
    }],
    betas=["files-api-2025-04-14"]  # beta header 必要
)

# STEP 3: 何度でも同じ file_id で参照可能
response2 = client.beta.messages.create(
    model="claude-opus-4-7",
    max_tokens=2048,
    messages=[{
        "role": "user",
        "content": [
            {"type": "document", "source": {"type": "file", "file_id": file_id}},
            {"type": "text", "text": "今度は表データを抽出して"}
        ],
    }],
    betas=["files-api-2025-04-14"]
)

④ API メソッド一覧

メソッド用途
client.beta.files.upload(...)ファイルアップロード → file_id 取得
client.beta.files.list()アップロード済みファイル一覧
client.beta.files.retrieve(file_id)file_id でメタデータ取得
client.beta.files.delete(file_id)削除
client.beta.files.content(file_id)ファイル中身ダウンロード

⑤ 制約条件

  • サイズ上限: 32MB / ファイル
  • 保存期間: 90日 (90日アクセスなしで自動削除)
  • 対応形式: PDF / JPEG / PNG / GIF / WebP / text/plain
  • 合計ストレージ: 100GB / 組織
  • beta header 必要: betas=["files-api-2025-04-14"]
注意: Files API はまだ beta。本番運用前に最新仕様を確認。GA (一般公開) 時に API が変わる可能性。

⑥ Prompt caching との組み合わせ

Files API は prompt caching (Lecture 60) と組み合わせると最強:

messages=[{
    "role": "user",
    "content": [
        {
            "type": "document",
            "source": {"type": "file", "file_id": file_id},
            "cache_control": {"type": "ephemeral"}  # ← cache 化!
        },
        {"type": "text", "text": "[毎回違うユーザー質問]"}
    ]
}]
# → 1回目: ファイル本体トークン (cache_creation)
# → 2回目以降: cache_read (90%OFF) で実質ほぼ無料
三重節約構造:
  1. Files API: base64再送信なし → ネットワーク削減
  2. Prompt caching: トークン料金 90%OFF
  3. file_id 一度発行 → ストレージ料金は無料 (90日まで)

⑦ ユースケース別

1. ヘルプデスクbot (社内マニュアル100ページ)

マニュアルPDFを Files API で1回アップロード → file_id を環境変数化。ユーザーが「○○のやり方は?」と聞くたびに file_id + prompt caching で即応答。90日に1回 file 更新 → upload 再実行 + file_id 入れ替え。

2. 契約書レビュー service

顧客の契約書PDFを Files API にアップロード → 「リスク条項抽出」「修正案提示」「比較分析」と複数の質問を同じ file_id で処理。30日後に自動削除 → プライバシー配慮 + ストレージ無駄なし。

3. 画像分析パイプライン (Batch API 連携)

1000枚の商品画像を Files API で一括アップロード → Batch API で「カテゴリ分類」「品質スコア」「商品説明文生成」を並列実行。base64再送信より圧倒的に高速。

⑧ ファイル管理ベストプラクティス

  • file_id を永続ストレージに記録: DB の documents.anthropic_file_id カラム等
  • ハッシュ管理: 同じファイルの重複upload を避けるため、SHA256 ハッシュで既存file_idを再利用
  • 定期チェック: 90日制限のため、月1で files.list() 確認 + 期限切れ近い物を再upload
  • 削除ポリシー: 用途終了したファイルは files.delete() で即削除 (法令遵守・コスト)

⑨ 中学生向けに例えると

学校の例えFiles API の対応
毎回先生に教科書のコピーを手渡すbase64直貼り
図書館に教科書を預けてカード番号で参照Files API + file_id
カード番号だけ控えていれば毎回コピー不要file_id 参照
「机に置きっぱ」と組み合わせると最速Files API + Prompt caching
核心: 「ファイルそのもの」を毎回送らない。「ファイルへの参照 (file_id)」 だけを送って、Anthropic 側に永続保存させる。

⑪ 理解度チェック

Q1. Files API は何のためにある?

「ファイルを事前にアップロードして、後で参照する」 ため。base64エンコードを毎回 messages に含めずに、file_id だけ送れば良い。同じファイルを複数回使うとき効果絶大。

Q2. 何と組み合わせると最強?

Prompt caching (Lecture 60)。Files API でファイル参照を軽量化 + caching でトークン料金90%OFF。ヘルプデスクbot等で「同じPDFについて1000回質問」のような用途では実質ほぼ無料化。

Q3. ファイル保持期間は?

90日。最後のアクセスから90日経過で自動削除。継続利用するなら定期的にアクセス or 再アップロードが必要。用途終了したファイルは files.delete() で即削除推奨 (プライバシー)。

Q4. beta header って何?

Files API はまだ beta なので betas=["files-api-2025-04-14"] をリクエストに付ける必要あり。GA (一般公開) されると不要になる予定。
