Providing examples— 例を見せて Claude を導く(one-shot / multi-shot)

Anthropic Academy / コース02 Claude with the Anthropic API

① show, not tell — 例で見せる力

「言葉で説明する」より「実例で見せる」方が、Claude が要件を理解しやすい。プロンプト内に input/output ペアを入れて応答を導くのが one-shot / multi-shot プロンプティング。

原則: show, not tell (語るな、見せろ)。説明では伝わらない「望ましい出力の特徴」が、例なら一発で伝わる。

② 具体例: サーカズム検出

ツイートが positive か negative か判定したい。説明だけだと サーカズム(皮肉) が判定できない。

図① 例なし(左：皮肉を見抜けず誤判定) vs 例あり(右：正しく Negative)

"Great game tonight!"
</sample_input>
<ideal_output>

</ideal_output>

<sample_input>
"Oh yeah, I really needed a flight delay tonight! Excellent!"
</sample_input>
<ideal_output>
Negative
</ideal_output>

XML タグで <sample_input> / <ideal_output> を分離(#33 の応用)。「サーカズムは慎重に」という文脈もセットで添える。

③ 例を使うべき場面

  • コーナーケース対応 (サーカズム / 二重否定 / 文化依存表現)
  • 複雑な出力フォーマット (特定の JSON 構造・テーブル形式)
  • スタイル・トーン の提示
  • 曖昧な入力 の扱い方を実演

④ One-shot vs Multi-shot

種類例の数向く場面
One-shot1つ基本パターン確立だけで十分なとき
Multi-shot複数様々なエッジケース・バリエーションをカバーしたいとき

⑤ Eval から良い例を見つける

プロンプト評価(#22-#28)で 最高スコアの出力 を例として再利用するのが効率的。

「score 10 の応答」を <ideal_output> に入れれば、Claude に「完璧な出力ってこういうもの」と直接示せる。評価パイプライン + 例提供 が綺麗につながる。

⑥ 「なぜ ideal か」を添えて強化

<ideal_output>
[例の出力]
</ideal_output>

This example is well-structured, provides detailed information
on food choices and quantities, and aligns with the athlete's
goals and restrictions.

「なぜこの出力が良いか」を説明文で添えると、Claude は「形式」だけでなく「良さの理由」まで学べる。

⑦ 答案見本の例えで覚える

図② 説明だけ(左) vs 100点見本+理由(右)

学校の例えプロンプト技法

⑨ 理解度チェック

Q1. なぜ「説明だけ」より「例」の方が効くの?

「望ましい出力の特徴」は言葉で説明しきれないことが多い。サーカズムや微妙なトーンは、実例で見せると一発で伝わる。「show, not tell」が原則。

Q2. One-shot と Multi-shot の使い分けは?

シンプルなパターン確立なら One-shot で十分。様々なエッジケース・バリエーションをカバーしたい時は Multi-shot で複数例を提供する。

Q3. 例を作るコツは?

プロンプト評価(#22-#28)で 最高スコアの応答 を例として再利用する。score 10 の出力を <ideal_output> に入れれば、「完璧な出力ってこういうもの」と直接示せる。

Q4. 例 + 「なぜ ideal か」を組み合わせる効果は?

形式だけでなく「良さの理由」まで Claude が学べる。「この答案は構成・具体例・結論の3点が揃ってる」と理由を解説する → 表面だけでなく本質を学べる。
