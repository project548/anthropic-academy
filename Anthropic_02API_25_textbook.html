Anthropic Academy / コース02 Claude with the Anthropic API

① 3つの関数で評価パイプラインを組み立てる

図① 3関数の階層構造(外側 run_eval → 内側 run_prompt)

外側から内側へ、責務を分けて積み重ねる。「全部を回す」「1ケースを回す」「1問解く」の3層構造。

② 各関数の中身

run_prompt

テストケースをプロンプトテンプレートに差し込み、Claude に送る。

def run_prompt(test_case, prompt_template):
    prompt = prompt_template.format(task=test_case['task'])
    messages = []
    add_user_message(messages, prompt)
    return chat(messages)

シンプル。1問解いて答えを返すだけ。

run_test_case

1ケース分の 実行 + 採点 + 結果まとめ。

def run_test_case(test_case):
    output = run_prompt(test_case)
    score = 10  # ← 今は仮ハードコード(本物の採点は #26 以降)
    return {
        "output": output,
        "test_case": test_case,
        "score": score
    }
注意: 今は score = 10 を固定で返している。「全部満点」のダミー採点。次の章で本物のグレーダーに差し替える。

run_eval

データセットを順番にループし、各ケースの結果をリストにまとめる。

def run_eval(dataset):
    results = []
    for test_case in dataset:
        result = run_test_case(test_case)
        results.append(result)
    return results

③ 実行のしかた

前章で作った dataset.json を読み込んで、run_eval に渡すだけ。

with open("dataset.json", "r") as f:
    dataset = json.load(f)

results = run_eval(dataset)
print(json.dumps(results, indent=2))
実行時間: Haiku モデルで 30秒程度(全データセット実行)。並列化やキャッシュは後の章で。

④ 結果の中身

図② 結果オブジェクトの3要素

実際の応答を見ると、Claude が 冗長 に返してくることが分かる(まだフォーマット指示がないため)。これが「プロンプトを改善する」動機になる。

⑤ 現時点で何ができたか

達成済み: データセットを Claude に通し、構造化された結果(output/test_case/score)を集める コア評価パイプライン が完成。
欠けピース: グレーダー(本物の採点ロジック)。ハードコード10を、応答内容を見て点数を出す仕組みに置き換える必要がある → #26 以降で実装。

⑥ 学校の例えで覚える

学校の例え評価パイプライン

⑧ 理解度チェック

Q1. 3つの関数の階層関係は?

外側から: run_eval(全件)→ run_test_case(1件)→ run_prompt(1問解くだけ)。責務を3層に分けて、それぞれ単純な役割にする。

Q2. なぜ今 score を 10 にハードコードしているの?

採点ロジックは複雑なので、いったん仮置きにして パイプライン全体が動く ことを確かめるため。次の章で本物のグレーダーに置き換える。

Q3. run_eval の戻り値はどんな形?

結果オブジェクトのリスト。各要素は {output, test_case, score} の3要素を持つ辞書。

Q4. Haiku で30秒かかる。もっと速くするには?

並列実行(複数テストケースを同時に Claude に投げる)・プロンプトキャッシュ(共通部分を再利用)等。後の章で扱う。
