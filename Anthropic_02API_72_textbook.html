Accessing resources— クライアントから resource を読み込む

Anthropic Academy / コース02 Claude with the Anthropic API

① 本章の目的

#71 で resource を 提供する側 を学んだ。本章は 使う側 。Claude or 自前クライアントから resource を読み込む方法。

② Python クライアントから読む

async with ClientSession(read, write) as session:
    await session.initialize()

    # 1. resource 一覧取得
    resources = await session.list_resources()
    for r in resources.resources:
        print(f"- {r.uri}: {r.name}")

    # 2. 特定 resource を読む (静的URI)
    content = await session.read_resource("config://app/settings")
    print(content.contents[0].text)

    # 3. 動的URI で読む
    doc = await session.read_resource("file://docs/intro")
    # → docs/intro.md の中身が返る

③ Claude が resource を読むパターン

Claude Desktop 等のクライアントでは、ユーザーが @で resource を指定 できる:

ユーザー: "@config://app/settings をベースに、本番用の設定を提案して"

# Claude Desktop が:
# 1. MCP server から resource を読込 (read_resource)
# 2. その内容を Claude API のmessages に含める
# 3. Claude が「現在の設定」を参考に提案を生成
核心: resource は ユーザーが明示的に「これを参考に」 と指定する。tool のように Claude が自動選択せず、明示参照されたものだけ context に入る。

④ resource vs tool — 呼ばれ方の違い

  • Tool: Claude が自動で「これ使うべき」と判断 → call_tool
  • Resource: ユーザーまたはアプリが「これ読んで」と明示指定 → read_resource

⑤ 中学生向けに例えると

Tool は「先生が自分で参考書を開いて答える」、Resource は「生徒が『この本のここを見て答えて』と指定する」。指示の主体が違う。

⑥ 理解度チェック

Q1. read_resource はいつ呼ばれる?

① ユーザーが明示的に @uri 指定したとき ② アプリが「この resource を context に入れる」と判断したとき。Claude 自動判断ではない。
