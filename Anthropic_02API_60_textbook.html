Prompt caching— 同じ前置きを再利用してコスト90%削減・レイテンシも短縮

Anthropic Academy / コース02 Claude with the Anthropic API

① まず結論 — Prompt caching って何?

同じ system prompt や長文ドキュメント を何度も使うとき、それを Anthropic 側でキャッシュして 2回目以降は10%料金 + 低レイテンシ で再利用できる機能。

典型ケース:
  • 100ページPDFについて何回も質問するチャットbot
  • 長い指示・例示を含む system prompt
  • RAGで毎回同じ chunk を Top-K に入れるパターン
  • tool スキーマ定義が大きい

② コスト効果 — 90%削減の正体

トークン種別料金倍率 (vs通常input)説明
cache_creation1.25倍 (初回)キャッシュ書き込み時
cache_read0.10倍 (= 90%OFF)キャッシュ読み出し時
通常input1.0倍キャッシュ非対象部分
output変化なし応答テキスト
採算分岐点: 同じ chunk を 2-3回 再利用すれば、cache_creation の +25% コストを cache_read の -90% で回収。回数が多いほど節約効果大。

③ 最小コード — cache_control を付ける

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": "あなたは社内ヘルプデスクです。以下のFAQに基づいて答えて。\n\n[FAQ 1000件...]",
            "cache_control": {"type": "ephemeral"}  # ← ここ!
        }
    ],
    messages=[{"role": "user", "content": "副業申請の手順は?"}],
)

print(response.usage)
# 初回: cache_creation_input_tokens=50000 (1.25倍料金)
# 2回目以降: cache_read_input_tokens=50000 (0.1倍料金 = 90%OFF)

④ どこにキャッシュを置く? — 階層構造

キャッシュは プロンプトの前置き部分 から始まる連続領域。途中で変わる箇所より 前 しかキャッシュできない。

system: [大きな指示 (cached)] [新情報なし]
       ↓
tools: [tool定義 (cached if before user msg)]
       ↓
messages[0..N-1]: [過去履歴 (cached)]
       ↓
messages[N]: [今回のユーザー質問 (毎回違う・cacheしない)]
原則: 「変わらない長い部分 をプロンプトの先頭に、変わる短い部分 を末尾に」。アーキテクチャ設計から意識する。

⑤ TTL (有効期限)

TTL料金用途
5分 (ephemeral・標準)cache_creation 1.25倍連続するチャットセッション
1時間 (extended)cache_creation 2.0倍長時間アクティブなセッション
注意: アクセスがあるとTTLが 毎回リセットされる。継続的に質問が来るチャットなら実質「永続キャッシュ」のように使える。
非アクティブが TTL を超えると自動失効 → 再アクセスで cache_creation 発生。

⑥ 複数の cache breakpoint

1つのリクエストに最大 4個 の cache_control を置ける。階層的キャッシュ:

system=[
    {"type": "text", "text": "[組織共通の指示]",
     "cache_control": {"type": "ephemeral"}},  # breakpoint 1
    {"type": "text", "text": "[このエージェント固有の指示]",
     "cache_control": {"type": "ephemeral"}}   # breakpoint 2
],
tools=[
    {..., "cache_control": {"type": "ephemeral"}}  # breakpoint 3
],
messages=[
    {"role": "user", "content": [
        {"type": "text", "text": "[毎回同じドキュメント]",
         "cache_control": {"type": "ephemeral"}},  # breakpoint 4
        {"type": "text", "text": "[ユーザー質問]"}
    ]}
]
メリット: 共通指示 + エージェント固有指示 + tool + ドキュメント — それぞれ別キャッシュ。1個だけ変えても他のキャッシュは生き残る。

⑦ キャッシュ対象の最小サイズ

  • Sonnet / Opus: 1024トークン以上
  • Haiku: 2048トークン以上
  • これ以下はキャッシュされない (cache_creation_input_tokens=0)
tips: 短い system prompt はキャッシュされない。長文 (FAQ・PDF・例示豊富な指示) を狙う。

⑩ 中学生向けに例えると

学校の例えprompt caching の対応
毎回先生に教科書全部を渡し直す通常input
先生の机に教科書を置きっぱなしにするprompt caching
「教科書はもう手元にある」前提で質問だけ送るcache_read
教科書を最初に置く手間 = +25%cache_creation
2回目以降の質問は教科書部分のお代がほぼ無料cache_read 0.1倍料金
核心: 「変わらない部分」と「変わる部分」を分けて、変わらない部分を 1回送って何度も使い回す。

⑫ 理解度チェック

Q1. Prompt caching の経済効果は?

cache_read は通常input の 10%料金 (90%OFF)。初回 cache_creation は 1.25倍 (25%増)。
→ 同じ chunk を 2-3回 再利用すれば cache_creation の追加コストを回収。

Q2. キャッシュはどこに置く?

「変わらない長い部分」をプロンプトの 前 に、「変わる短い部分」を 後 に置く。キャッシュは前置きから連続する領域のみ可能。

Q3. 何分間キャッシュは残る?

デフォルト 5分 (ephemeral)。アクセス毎にTTLリセット → 連続使用なら実質永続。長時間アクティブなら 1時間 (extended) プラン。

Q4. 最大いくつ cache_control 置ける?

4個。system / tools / messages の中で柔軟に階層化できる。
