Module 3 ・ Lecture 112 ・ 文脈操作

Adding context— Claude にプロジェクトの文脈を渡す方法

Anthropic Academy / コース04 Claude Code

① なぜ文脈が大事?

Claude は 渡された情報からしか判断できない。プロジェクトを知らない初心者と同じ。文脈を適切に与えると精度が劇的に上がる。

核心: 「文脈なし → 一般論」/ 「文脈あり → 業務特化の的確な答え」。文脈を渡す技 = Claude Code の生産性そのもの。

② 文脈を追加する5つの手段

  1. 自然言語で説明: 「このプロジェクトは Express ベースの API サーバで…」
  2. ファイル参照: @ でファイル添付 (例: @src/auth.ts)
  3. CLAUDE.md: 永続的な文脈 (起動時に自動読込)
  4. Glob / Grep tool: Claude が必要に応じて自分で探す
  5. 外部資料: URL を貼る → WebFetch で取得

③ @ で添付の使い方

# セッション内で
> @package.json の依存関係を整理して

> @src/auth/login.ts と @src/auth/logout.ts の重複を抽出して

# ディレクトリも添付可能
> @docs/ の全ファイルを読んで API 仕様をまとめて

④ CLAUDE.md による永続的文脈

CLAUDE.md に書いた内容は 毎セッション 自動で読まれる。「毎回同じ説明」を省略できる。

# プロジェクト固有 CLAUDE.md 例
## 重要な前提
- Node.js 20 / TypeScript 5.4 / Vitest
- DB: PostgreSQL 16 (本番に直接接続しない)
- 認証: JWT + Refresh token
- スタイル: ESLint + Prettier (npm run lint で確認)

## やってほしくないこと
- console.log のままコミットしない
- any 型を使わない (unknown + 型ガードを使う)
- 本番 DB に直接クエリしない

⑤ 文脈の与え方ベストプラクティス

  • 必要なものだけ: 全部入れると context が膨らんで遅くなる
  • 具体的に: 「あのファイル」より @src/utils/date.ts:42
  • 制約も伝える: 「ライブラリ追加禁止」「TypeScript 厳密モード」等
  • 目的を1文で: 「○○のために△△したい」
  • 失敗パターンも教える: 「過去にこれで詰まった」

⑥ 中学生向けに例えると

転校生に学校を案内するイメージ。「ここが教室」「ここは入っちゃダメ」「先生はこういう人」を最初に伝えるほど、転校生 (Claude) はその日から戦力になる。
