Quiz on prompt engineering techniques— プロンプトエンジニアリング手法のテスト

Anthropic Academy / コース02 Claude with the Anthropic API

① 範囲・取り組み方

#22〜#35 で学んだ「プロンプトエンジニアリング」を総点検する Quiz 回。10問中 8問正解で実務レベル。

カバー領域: Clear and direct / Role assignment / XML 構造化 / Few-shot / Chain-of-thought / Output formatting / 反復改善。

② 問題セット

Q1. 「曖昧な指示」と「具体的な指示」、Claude にどちらが効きやすい?

A. 具体的な指示。出力形式 / 対象 / 制約を明示するほど精度が上がる。

Q2. Few-shot prompting とは?

A. 入力/出力ペアの例を数個提示して、望ましい応答パターンを学習させる手法。抽象的指示より実例の方が効く。

Q3. XML タグを使う主な目的は?

A. プロンプト内の各部分 (context / instruction / example / output) を 明確に区切る。Claude は学習データで XML 構造を多く見ているので認識精度が高い。

Q4. Role assignment (役割付与) の例は?

A. system prompt で「あなたはベテラン編集者です」「あなたは厳しい採点者です」のように 役割を与える。出力スタイル・観点が役割に沿って制御される。

Q5. Chain-of-thought (思考の連鎖) とは?

A. 「ステップごとに考えて答えて」と指示し、推論過程を明示的に書き出させる手法。数学・論理・複雑な判断で精度が上がる。

Q6. JSON 出力を安定化させる方法は?

A. ① 出力例を Few-shot で示す ② スキーマを XML タグで明示 ③ "Respond in JSON only" 等を明記 ④ tool use で構造化出力を強制。

Q7. プロンプトの「失敗」を改善するアプローチは?

A. 反復改善 (Iterative refinement)。① 結果を観察 → ② 何が違うかを分析 → ③ 制約を追加 / 例を増やす → ④ 再実行。1発で完璧を目指さない。

Q8. 出力の冗長性を抑えるには?

A. "Be concise"、出力フォーマット指定 (箇条書き3点等)、role assignment で「短く要約する人」を割り当てる、stop_sequence で長文化を打ち切る、等。

Q9. プロンプトの順序効果 (重要なもの後ろ)

A. 長い prompt では 末尾の指示 が記憶に残りやすい (recency bias)。最重要指示は末尾に置く、または冒頭+末尾で繰り返すのが定石。

Q10. プロンプトエンジニアリングとファインチューニングの違いは?

A. プロンプトエンジニアリング = モデルを変えずに 入力を工夫。ファインチューニング = モデル本体を 追加学習。前者は即時・低コスト、後者は時間・コスト要。
