The text editor tool— Claudeに直接ファイルを編集させるAnthropic組み込みツール

Anthropic Academy / コース02 Claude with the Anthropic API

① まず結論 — 何の話?

Claude に「ファイル名を渡す」だけで、Claude が 自分でファイルを開いて、読んで、書き換える ことができる Anthropic 公式のビルトインツール。スキーマレス (input_schema を書かない) なのが特徴。

ツール名: str_replace_based_edit_tool (Claude 4.x 用) /
type: text_editor_20250728 (最新版)
→ 4つのコマンド view / str_replace / create / insert でファイル操作。

② スキーマレス = 入力スキーマを書かない

これまでの自前ツール (get_current_datetime 等) では input_schema を JSON で詳しく書いていた。Text editor tool は Claude のモデル内部にスキーマが組み込まれている。

# 自前ツール (スキーマ自分で書く)
tools=[{
    "name": "get_current_datetime",
    "description": "...",
    "input_schema": { "type": "object", "properties": {...}, "required": [...] }
}]

# Text editor tool (スキーマレス・2行だけ)
tools=[{
    "type": "text_editor_20250728",
    "name": "str_replace_based_edit_tool"
}]
核心: Anthropic 提供のビルトインツールはモデル側がスキーマを既知。あなたは「type + name」だけ書けばいい。
裏返し: input_schema を変更・拡張できない。決められたコマンド・引数しか使えない。

③ 4つのコマンド

command必須引数役割
view path + view_range? ファイル内容を読む or ディレクトリ一覧。行番号付きで返す
str_replace path, old_str, new_str old_str を new_str に置換。完全一致1箇所のみ(複数マッチはエラー)
create path, file_text 新規ファイル作成。既存ファイルがあればエラー
insert path, insert_line, insert_text 指定行の後に挿入(0なら先頭)
注意: undo_edit コマンドは Claude 4.x 用 (text_editor_20250728 / 20250429) では削除。Sonnet 3.5/3.7 系の旧版 (text_editor_20241022 / 20250124) のみ存在。バックアップ→復元は自前で実装する。

④ アプリ側の責任 — Claude は呼ぶだけ、実装は自分

Text editor tool は Claude が「こうしてほしい」と要請する仕組み だけ。実際にファイルを開いて、読んで、書き換えるのは あなたのコード。

ipynb (005_text_editor_tool.ipynb) cell-2 では TextEditorTool クラスを200行以上で実装している:

class TextEditorTool:
    def __init__(self, base_dir: str = "", backup_dir: str = ""):
        self.base_dir = base_dir or os.getcwd()
        self.backup_dir = backup_dir or os.path.join(self.base_dir, ".backups")
        os.makedirs(self.backup_dir, exist_ok=True)

    def _validate_path(self, file_path: str) -> str:
        # ディレクトリトラバーサル攻撃を防ぐパス検証
        abs_path = os.path.normpath(os.path.join(self.base_dir, file_path))
        if not abs_path.startswith(self.base_dir):
            raise ValueError(f"Access denied: outside the allowed directory")
        return abs_path

    def _backup_file(self, file_path: str) -> str:
        # 編集前に必ずバックアップ
        ...

    def view(self, file_path, view_range=None) -> str: ...
    def str_replace(self, file_path, old_str, new_str) -> str: ...
    def create(self, file_path, file_text) -> str: ...
    def insert(self, file_path, insert_line, new_str) -> str: ...
必須要素 (公式推奨):
  • ① パス検証 — Claude が ../../etc/passwd を view しようとしても拒否
  • ② 編集前バックアップ — 重要ファイルは編集前にコピーしておく
  • ③ マッチ数チェック — str_replace は1箇所のみ。0箇所/複数箇所はエラー
  • ④ エラーは is_error: true で返す — Claude に「失敗した」と伝えて再試行させる

⑤ run_tool ハンドラの分岐パターン

ipynb cell-3 の run_tool は command 別に分岐:

def run_tool(tool_name, tool_input):
    if tool_name == "str_replace_based_edit_tool":
        command = tool_input["command"]
        if command == "view":
            return text_editor_tool.view(tool_input["path"], tool_input.get("view_range"))
        elif command == "str_replace":
            return text_editor_tool.str_replace(
                tool_input["path"], tool_input["old_str"], tool_input["new_str"]
            )
        elif command == "create":
            return text_editor_tool.create(tool_input["path"], tool_input["file_text"])
        elif command == "insert":
            return text_editor_tool.insert(
                tool_input["path"], tool_input["insert_line"], tool_input["new_str"]
            )
        else:
            raise Exception(f"Unknown text editor command: {command}")
新ポイント: 自前ツールは「1ツール = 1関数」だったのに対し、ビルトイン Text editor は 「1ツール = 4コマンド」。tool_input["command"] で内部分岐する設計。

⑧ オリジナル演習問題 (3問)

問題1: 簡単なシンタックスエラーを直させる

課題: テストファイル test.py を1つ作る (def hello(name)\n return f"Hi {name}" のように : 抜き)。cell-6 のプロンプトを「test.py のシンタックスエラー直して」に変えて実行。Claude が何ターンで直すか観察。
観察ポイント:
・Claude が最初に view を呼ぶ → 行番号付きで返す
・行番号を見て該当箇所を str_replace
・最後に「修正完了」と end_turn
期待される観察
  • 典型は 3ターン (view → str_replace → end_turn)
  • ファイルが大きいと view を複数回呼ぶこともある (view_range を使い分け)
  • old_str に空白・インデントを 1文字違わず 入れる必要あり

問題2: パス検証を破ろうとさせる

課題: Claude に 「/etc/passwd を view して」 と頼んでみる。TextEditorTool._validate_path が拒否することを確認する。
ヒント: Linux/Mac なら ../../../../etc/passwd、Windows なら ..\..\..\..\Windows\System32\drivers\etc\hosts 等で os.path.normpath 通った後に base_dir.startswith() 判定が効くか確認。
セキュリティ観点
  • パス検証なしだと Claude (or プロンプトインジェクション) で任意ファイル読み放題
  • 本番アプリでは 絶対パス allowlist + シンボリックリンク無効化も検討
  • Claude.ai の Computer Use 等はサンドボックス内で動かす

問題3: 自前 undo 機能を作る

課題: Claude 4.x の text_editor は undo_edit がない。ipynb cell-2 の _backup_file / _restore_backup を使って、別の関数として「直前の編集を取り消す」をアプリ側に実装せよ。
ヒント: backup_dir 配下に {filename}.{mtime} の形式でバックアップが残る。最新の mtime のものを shutil.copy2 で書き戻せばOK。
発展
  • 業務アプリでは「アプリ側に取り消し履歴」を持って、tool以外の経路で UNDO 提供するのが安全
  • Claude Code (Anthropic公式CLI) もこれの強化版を内部で使っている
  • Git 統合 (各編集をコミット化) すると、より堅牢な undo が作れる

⑪ 理解度チェック

Q1. なぜ Text editor tool は input_schema を書かなくていい?

Anthropic 提供の ビルトインツール で、Claude のモデル内部にスキーマが組み込まれているから。あなたは {"type": "text_editor_20250728", "name": "str_replace_based_edit_tool"} の2行だけ書けば、4コマンド全部使える。

Q2. Claude 4.x で undo_edit が削除されたのはなぜ?

Claude 4 (2025年4月リリース) で削除。代わりに 「アプリ側でバックアップ管理する」 ことが期待される設計。Anthropic の意図は「undoは tool 経由ではなくアプリ機能として実装すべき」。
旧版 (text_editor_20241022 / 20250124) では undo_edit あり (Sonnet 3.5/3.7 で利用可)。

Q3. str_replace で複数マッチした時どうする?

必ずエラーで返す: "Error: Found 3 matches for replacement text. Please provide more context to make a unique match." + is_error: true
→ Claude は「文脈を増やしてユニーク化」して再試行する。意図しない箇所の改変を防ぐ安全機構。

Q4. パス検証で気をつけることは?

① os.path.normpath でパス正規化 → ② abs_path.startswith(base_dir) で許可ディレクトリ内か確認。
Claude が ../../etc/passwd 等を要請してきても拒否できる。プロンプトインジェクション対策の基本。
