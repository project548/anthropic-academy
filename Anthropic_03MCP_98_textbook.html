The server inspector— MCP Inspector で server を可視化・デバッグする

Anthropic Academy / コース03 Model Context Protocol

① MCP Inspector とは?

MCP Inspector は、MCP server を ブラウザ UI で対話的にテスト できる開発者向けツール。Anthropic が公式提供。サーバの tool / resource / prompt を一覧表示し、引数を入れて手動実行できる。

核心: Claude Desktop に登録する前の動作確認に必須。「サーバが正しく起動するか」「tool が一覧に出るか」「実行結果が期待通りか」をブラウザ画面で素早く検証。

② 起動方法

# プロジェクトディレクトリで
uv run mcp dev server.py

# → 自動でブラウザが開く (http://localhost:5173 等)
# → 別ターミナルから手動でも起動可:
npx @modelcontextprotocol/inspector uv run server.py

③ Inspector 画面の構成

  • 左ペイン: server 接続状態 / 接続/切断ボタン
  • タブ切替: Tools / Resources / Prompts / Sampling / Logs
  • Tools タブ: 定義された tool 一覧 + 各 tool の input フォーム + Run ボタン + 結果表示
  • Resources タブ: 公開されてる resource (ファイル・URL) の一覧 + 読み込みプレビュー
  • Logs タブ: サーバとの全通信 (JSON-RPC メッセージ) を確認可能

④ 典型的なデバッグフロー

  1. uv run mcp dev server.py で Inspector 起動
  2. Tools タブで自分の tool が一覧に出ているか確認
  3. 各 tool の description が LLM に分かりやすく書けているか目視チェック
  4. 引数フォームに値を入れて Run → 結果が期待通りか
  5. エラー時は Logs タブで JSON-RPC やり取りを確認
  6. OK なら Claude Desktop の config に登録

⑤ Inspector が解決してくれる「あるある」

  • Claude Desktop に登録したのに tool が出ない → Inspector で起動確認 → そもそも server が落ちてた / tool 名タイポ
  • tool 実行で謎エラー → Inspector で同じ引数を流して再現 → スタックトレースが見える
  • 引数のバリデーションが効かない → Inspector で間違った型を入れて検証
  • resource の URI 設計が悩ましい → Inspector でクライアントから見える形をプレビュー

⑥ Inspector vs Claude Desktop

  • Inspector: 開発時の単体テスト用 (LLM 経由しない・手動実行)
  • Claude Desktop: 本番運用 (LLM が自動で tool を選んで呼ぶ)

両方を使い分ける。実装中は Inspector、ローカルE2Eなら Desktop。

⑦ 中学生向けに例えると

家電を本番設置する前に「テスト棚」で動作確認するイメージ。Inspector は MCP server の試運転台。ボタン押して中身を確かめてから、Claude Desktop (本番リビング) に持っていく。

⑧ 理解度チェック

Q1. Inspector の起動コマンドは?

A. uv run mcp dev server.py。自動でブラウザが開く。

Q2. Inspector でデバッグが捗る場面は?

A. Claude Desktop に登録する前の動作確認 / tool 実行エラーの再現 / JSON-RPC メッセージの確認。

Q3. Inspector と Claude Desktop の使い分けは?

A. Inspector = 開発者の単体テスト / Claude Desktop = LLM 経由の本番運用。両方使う。
