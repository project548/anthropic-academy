② 「準備」と「実行」を分ける重要性

フェーズステップ頻度計算量
事前準備1. chunk / 2. embed / 3. store1回 (or 更新時)大 (全文書をembedding)
実行時4. search / 5. generateユーザー質問ごと小 (1質問だけembed)
核心: 100万件のchunkがあっても、事前準備は1回だけ。実行時は1質問あたり数百msで完結する。
→ 文書追加・更新時のみ準備を「差分実行」すれば、運用負荷は低い。

③ VectorIndex クラスの設計 (本コース ipynb)

#55 で完全実装するクラスの輪郭:

class VectorIndex:
    def __init__(self, distance_metric="cosine", embedding_fn=None):
        self.vectors = []      # ベクトルのリスト
        self.documents = []    # 元 chunk (メタデータ込み)
        self._embedding_fn = embedding_fn  # generate_embedding を渡す

    def add_document(self, document):
        """文書追加: embedding を生成して保存"""
        vector = self._embedding_fn(document["content"])
        self.vectors.append(vector)
        self.documents.append(document)

    def search(self, query, k=1):
        """類似検索: クエリをembedding → 全vector と距離計算 → 上位k件"""
        query_vector = self._embedding_fn(query)
        distances = [(self._cosine_distance(query_vector, v), doc)
                     for v, doc in zip(self.vectors, self.documents)]
        distances.sort(key=lambda x: x[0])
        return distances[:k]
シンプル実装の威力: Pinecone等の本格DBを使わなくても、Python list + 全件スキャンで動く。チャンク数が10万件以下なら実用十分。

④ プロンプト設計 — 検索結果の渡し方

# 良いプロンプト例
system_prompt = """
あなたは社内ヘルプデスクです。以下の参考資料に基づいて答えてください。
資料に書いていないことは「資料に記載なし」と答え、推測しないでください。
"""

results = store.search(user_question, k=3)

user_message = f"""
<参考資料>
{results[0][0]["content"]}
---
{results[1][0]["content"]}
---
{results[2][0]["content"]}
</参考資料>

<質問>
{user_question}
</質問>
"""
3つのコツ:
  1. XMLタグで区切る — Claudeが「参考資料」と「質問」を明確に区別
  2. 「資料に書いていないことは推測しないで」 — 幻覚抑制
  3. citation を返してもらう — 「どの資料を見て答えたか」を明示させる

⑤ よくある失敗パターン

失敗1: 検索結果に該当chunkが無い

原因: chunking が悪い / embedding model が用途に合わない / クエリの言い回しと文書の言い回しが乖離
対策: ① chunk size 見直し ② hybrid search (BM25 + embedding 併用) ③ クエリ拡張 (Claude に「言い換え」させてから検索)

失敗2: Claude が「参考資料を見ずに」幻覚

原因: system_prompt が弱い / 関連chunk が低品質で「自分の知識で補完しよう」と判断
対策: system_prompt を強化 ("資料に書いていないなら『情報なし』と答えること") + 検索精度向上

失敗3: top-k が大きすぎてノイズ過多

原因: k=10 等で多すぎるchunk を渡す → Claude が混乱
対策: 通常 k=2-5。reranker (二次フィルタ) を入れる手もある

失敗4: 文書を更新したのに古い embedding のまま

原因: 事前準備を再実行していない
対策: 文書更新時に対応 chunk を delete + 新規 chunk を add するスクリプト (差分更新)

⑦ 中学生向けに例えると

学校の例えRAG flow の対応
教科書を全部読んで重要箇所に付箋を付けるchunk + embedding (準備)
付箋を本棚に意味別に整理 (動物の本・乗り物の本…)vector store
テスト中に「カエルの心臓」と聞かれるユーザー質問
「動物」付箋エリアから関連ページを2-3枚取り出す類似検索 top-k
取り出したページを読んで答えるClaude が生成
核心: 全部覚えない。「索引と本棚」を作っておいて、必要なときだけ該当ページを開く。RAGはこの「整理術」をAIに教える技術。

⑨ 理解度チェック

Q1. RAG の5ステップは?

事前準備 (1) chunk → (2) embed → (3) store / 実行時 (4) search → (5) generate

Q2. 事前準備と実行時の違いは?

事前準備は 1回だけ (or 文書更新時)・計算量大。実行時はクエリごとに小さく完結。100万chunkあっても1質問は数百msで返せる。

Q3. top-k はどれくらいが推奨?

通常 k=2-5。大きすぎるとClaudeがノイズで混乱、小さすぎると関連情報を見逃す。
質問の複雑さで調整: シンプル問い → k=2 / 複雑問い → k=5 / 文書横断比較 → k=10+ reranker

Q4. 幻覚 (hallucination) を抑制するコツは?

① system_prompt で明示: 「資料に書いていないことは『情報なし』と答えよ」
② XMLタグで参考資料を区切る: Claude が「ここ以外は知らない」と認識
③ citation を返してもらう: どのchunkを根拠にしたか明示させる
④ 検索精度向上: そもそも関連chunkが取れていれば幻覚は減る
