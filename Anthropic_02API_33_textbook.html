Structure with XML tags— XMLタグでプロンプトを整理する

Anthropic Academy / コース02 Claude with the Anthropic API

① なぜ構造が大事か

プロンプトに大量のデータを混ぜると、Claude が「どこからどこまでが指示で、どこからがデータか」を判別しづらくなる。

図① タグなし(左：混乱) vs XMLタグで構造化(右：明確)

② 強力な例: コード + ドキュメント

「このコードをこのドキュメント参考にデバッグして」というプロンプトで、混在状態を分離する。

<my_code>
def hello():
    print("hi")
</my_code>

<docs>
The print() function outputs to stdout.
</docs>
効果: Claude は「<my_code> 側がデバッグ対象」「<docs> 側が参考情報」と即座に区別できる。

③ カスタムタグ名のコツ

XML 公式仕様に従う必要はない。内容を物語る名前 を使うのがコツ。

良いタグ名イマイチなタグ名
<sales_records><data>
<athlete_information><info>
<my_code><text>
<docs><content>
原則: タグ名が具体的なほど、Claude は「このセクションの目的」を理解しやすい。

④ XMLタグを使うべき場面

  • 大量のコンテキストやデータ を含めるとき
  • 異なる種類のコンテンツ(コード/ドキュメント/データ)を混ぜるとき
  • コンテンツ境界を 特に明確にしたい とき
  • 複数の変数を挿入する複雑なプロンプト
短いコンテンツでも、区切り文字としての役割で構造を明確にできる。

⑤ 実例: 運動家のメニュー提案

<athlete_information>
- Height: 6'2"
- Weight: 180 lbs
- Goal: Build muscle
- Dietary restrictions: Vegetarian
</athlete_information>

Generate a meal plan based on the athlete information above.

→ Claude は「身長・体重・目標・制限の4つは関連する運動家データ」と即座に把握、それを総合的に考慮してメニューを作る。

⑧ 理解度チェック

Q1. XML タグを使うと何が良くなる?

Claude が「指示/データ/参考資料」の境界を即座に判別できる。大量のコンテンツを挿入する複雑なプロンプトで特に効果が大きい。

Q2. タグ名は <data> でいいの?

NG ではないが、具体的な名前 の方が遥かに効果的。<sales_records> や <athlete_information> のように、内容が一目で分かる名前を使う。

Q3. 短いプロンプトでも XML タグを使うべき?

劇的な効果は出にくいが、区切り文字として「これは外部入力データだ」と明示できるので使って損はない。プロンプトが複雑化したときに、最初から構造化しておくのが楽。

Q4. コードとドキュメントを混ぜる時の使い方は?

<my_code>...</my_code> と <docs>...</docs> で明示的に分離する。これで Claude は「どっちがデバッグ対象で、どっちが参考か」を即座に区別できる。
